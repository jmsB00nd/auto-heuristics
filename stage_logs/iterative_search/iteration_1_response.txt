## Novel Heuristic Design

**STRATEGY:** Polynomial Qubit-Coupling Resonance

**INTUITION:** Gates sharing a logical qubit are *coupled*: routing one without the other creates cascading bottlenecks that a purely additive sum misses entirely. By penalizing the *product* of distances for every gate-pair competing for the same qubit (a second-order polynomial interaction term), we directly model joint routing difficulty — a qubit with two distant partners is superlinearly worse than two separate single-partner qubits.

---

```python
def qlosure_poly_heuristic(self, swap_gate):
    import math

    # ── Step 1: Collect gate distances, criticalities, and layer weights ─────
    gate_dist   = {}  # gate_id -> physical distance under temp mapping
    gate_crit   = {}  # gate_id -> criticality (transitive closure + 1)
    gate_weight = {}  # gate_id -> layer-position discount

    for g in self.front_layer:
        q1, q2 = self.access2q[g]
        Q1 = self.temp_mapping_dict[q1]
        Q2 = self.temp_mapping_dict[q2]
        gate_dist[g]   = self.distance_matrix[Q1][Q2]
        gate_crit[g]   = self.dag_dependencies_count[g] + 1
        gate_weight[g] = 1.0

    for g in self.extended_layer:
        if g in gate_dist:          # already resolved via front layer → skip
            continue
        q1, q2 = self.access2q[g]
        Q1 = self.temp_mapping_dict[q1]
        Q2 = self.temp_mapping_dict[q2]
        gate_dist[g]   = self.distance_matrix[Q1][Q2]
        gate_crit[g]   = self.dag_dependencies_count[g] + 1
        depth          = self.extended_layer_index.get(g, 0) + 1
        gate_weight[g] = 1.0 / depth

    n_gates = len(gate_dist)
    if n_gates == 0:
        return 0.0

    # ── Step 2: Build logical-qubit → gate list ──────────────────────────────
    # Derived feature: which gates compete for the same logical qubit
    qubit_to_gates = {}
    for g in gate_dist:
        for lq in self.access2q[g]:
            qubit_to_gates.setdefault(lq, []).append(g)

    # ── Step 3: First-order linear distance term (gate-count normalised) ─────
    # Same spirit as baseline but normalised by actual gate count, not layer size.
    first_order = sum(
        gate_weight[g] * gate_crit[g] * gate_dist[g]
        for g in gate_dist
    ) / n_gates

    # ── Step 4: Second-order polynomial coupling term ─────────────────────────
    # Core novelty: for every PAIR of gates sharing a logical qubit, penalise
    # their *joint* routing difficulty via the product d_i × d_j.
    #
    # Why this works:
    #   • d_i=1, d_j=1  → product = 1   (both nearly done, no contention)
    #   • d_i=3, d_j=1  → product = 3   (one distant, modest penalty)
    #   • d_i=3, d_j=3  → product = 9   (both distant, superlinear penalty)
    #
    # The qubit's own decay scales the coupling: a "hot" qubit makes its
    # contention even costlier.
    coupling_score = 0.0
    n_pairs = 0

    for lq, gates in qubit_to_gates.items():
        phys_lq     = self.temp_mapping_dict[lq]
        qubit_decay = self.decay_parameter[phys_lq]

        for i in range(len(gates)):
            for j in range(i + 1, len(gates)):
                gi, gj = gates[i], gates[j]
                di, ci, wi = gate_dist[gi], gate_crit[gi], gate_weight[gi]
                dj, cj, wj = gate_dist[gj], gate_crit[gj], gate_weight[gj]

                # Harmonic mean of criticalities: a low-priority partner cannot
                # inflate the score of a high-priority one.
                hmean_crit = (2.0 * ci * cj) / (ci + cj)

                # Geometric mean of layer weights: balanced front/extended blend.
                geo_weight = math.sqrt(wi * wj)

                # Polynomial kernel: joint routing cost of this contending pair.
                coupling_score += qubit_decay * geo_weight * hmean_crit * (di * dj)
                n_pairs += 1

    if n_pairs > 0:
        coupling_score /= n_pairs

    # ── Step 5: Thermal penalty on the candidate SWAP ────────────────────────
    # SUM of both swap-qubit decays (not max): both qubits contribute heat.
    swap_heat = self.decay_parameter[swap_gate[0]] + self.decay_parameter[swap_gate[1]]

    # ── Final cost: heated first-order + second-order coupling ───────────────
    H = swap_heat * first_order + coupling_score

    return H
```

### Design Rationale vs. Baseline

| Dimension | Baseline | This Heuristic |
|---|---|---|
| **Interaction order** | Linear sum over independent gates | Quadratic cross-terms for gate pairs sharing a qubit |
| **Coupling signal** | None — gates treated independently | `d_i × d_j` product = joint routing bottleneck |
| **Criticality blending** | Additive `(deps+1) × d` | Harmonic mean of criticalities per pair |
| **Layer weight mixing** | Hard-coded `1/layer_factor` | Geometric mean of the two gates' weights |
| **Decay application** | `max(decay)` multiplied globally | `sum(decay)` on swap + per-qubit decay on each coupling |
| **Normalization** | By `front_layer_size` / `extended_layer_size` | By total gate count + total pair count |

The critical structural difference is the **second-order coupling term**: the baseline can never distinguish between *one gate at distance 6* versus *two gates at distances 3+3 sharing a qubit*, yet the latter creates a far harder routing subproblem — this heuristic penalizes it `9×` harder than `1×1`, versus identically in the baseline.
