Now I have a full picture of the class state. Key observations:
- `mapping_dict` is modified **in-place** only after the best swap is chosen (line 239), so I can detect which SWAP was applied on the *next* step's first heuristic call
- `temp_mapping_dict` is a separate copy, so `mapping_dict` is stable during all candidate evaluations within one step
- `reverse_mapping_dict` gives physical→virtual lookup

The CCRC design:
- Lazily detect mapping changes between steps → extract which physical qubit pair was last SWAPped → maintain a rolling window of size `k`
- For each front/extended gate, check if either of its virtual qubits is currently mapped to one of those recently-SWAPped physicals → apply continuity discount `β`

```python
def qlosure_poly_heuristic(self, swap_gate):
    beta = 0.35  # continuity reward: fraction by which distance is discounted for chained gates
    k = 5        # number of recent SWAP steps to consider as "chain context"
    W = 1.0

    # ── Lazy-initialize chain tracking state ─────────────────────────────────
    if not hasattr(self, '_ccrc_prev_mapping'):
        self._ccrc_prev_mapping = dict(self.mapping_dict)
        self._ccrc_recent_phys  = []   # ring buffer, each entry = set of physical qubits in a past SWAP

    # Detect whether the committed mapping changed since the last call.
    # mapping_dict is only updated in-place AFTER the best swap is chosen, so
    # this fires exactly once per routing step (on the first candidate call of the next step).
    changed_virt = [
        virt for virt, phys in self.mapping_dict.items()
        if self._ccrc_prev_mapping.get(virt) != phys
    ]
    if changed_virt:
        # The two virtual qubits whose physical slots changed → their OLD physical slots
        # are exactly the two qubits that were swapped.
        swapped_phys = {self._ccrc_prev_mapping[v] for v in changed_virt}
        self._ccrc_recent_phys.append(swapped_phys)
        if len(self._ccrc_recent_phys) > k:
            self._ccrc_recent_phys.pop(0)
        self._ccrc_prev_mapping = dict(self.mapping_dict)

    # Build the set of virtual qubits currently residing in recently-SWAPped physical slots
    recent_phys_union = set().union(*self._ccrc_recent_phys) if self._ccrc_recent_phys else set()
    chain_virtual = {
        virt for virt, phys in self.mapping_dict.items()
        if phys in recent_phys_union
    }

    # ── Standard bookkeeping ─────────────────────────────────────────────────
    front_layer_size    = len(self.front_layer)
    extended_layer_size = len(self.extended_layer)
    max_decay = max(self.decay_parameter[swap_gate[0]], self.decay_parameter[swap_gate[1]])

    # ── Front layer: dependency-weighted distance with continuity discount ───
    f_distance = 0.0
    for g in self.front_layer:
        q1, q2 = self.access2q[g]
        Q1 = self.temp_mapping_dict[q1]
        Q2 = self.temp_mapping_dict[q2]
        deps = self.dag_dependencies_count[g]

        # If either virtual qubit is in a recently-visited physical region,
        # grant a continuity bonus: the router is already "warm" in that area.
        in_chain = (q1 in chain_virtual) or (q2 in chain_virtual)
        weight = (1.0 - beta) if in_chain else 1.0

        f_distance += weight * (deps + 1) * self.distance_matrix[Q1][Q2]

    # ── Extended layer: same continuity weighting, decayed by lookahead depth ─
    e_distance = 0.0
    for g in self.extended_layer:
        q1, q2 = self.access2q[g]
        Q1 = self.temp_mapping_dict[q1]
        Q2 = self.temp_mapping_dict[q2]
        layer_factor = self.extended_layer_index.get(g, 0) + 1
        deps = self.dag_dependencies_count[g]

        in_chain = (q1 in chain_virtual) or (q2 in chain_virtual)
        weight = (1.0 - beta) if in_chain else 1.0

        e_distance += weight * (deps + 1) * self.distance_matrix[Q1][Q2] / layer_factor

    H = max_decay * (
        f_distance / front_layer_size
        + W * ((e_distance / extended_layer_size) if extended_layer_size else 0.0)
    )

    return H
```

---

**How it differs fundamentally from the baseline**

| Aspect | Baseline | CCRC |
|---|---|---|
| Distance weight per gate | `(deps+1)` — static, topology-blind | `weight * (deps+1)` — dynamically discounted by chain context |
| Temporal state | None (stateless per call) | Maintains a rolling window of the last `k` committed SWAPs |
| Routing bias | Greedy toward closer qubits everywhere equally | Preferentially continues routing along "warm" qubit regions |
| Motivation | Minimize total remaining distance | Minimize total distance **+ penalize erratic qubit-region jumps** |

**Key design decisions**

- **Lazy change-detection**: because `mapping_dict` is modified in-place only once per routing step, comparing it to `_ccrc_prev_mapping` at heuristic call time is cheap and exactly identifies which physical pair was SWAPped.
- **Physical→virtual re-lookup**: `chain_virtual` always reflects the *current* mapping so it correctly tracks qubits even as the mapping evolves.
- **β = 0.35**: reduces chained gate distance by 35%, strong enough to create routing momentum without overwhelming the global distance signal.
- **k = 5**: corresponds roughly to the depth of a typical SWAP chain for a 2-qubit gate on heavy-hex / grid topologies.
