IDEA_NAME: Chain Continuity Reward Cost (CCRC)
DESCRIPTION: Track the set of recently-executed gates (within the last k routing steps). For each gate g in the front/extended layer, if one of its virtual qubits also appeared in a recently-executed gate, reduce its effective distance weight by a continuity bonus β ∈ (0,1). The idea is that the routing algorithm has already "moved" toward this qubit's region; continuing the chain is cheaper. Gates with no chain context receive full weight 1. This rewards the algorithm for maintaining routing momentum along sequential gate chains rather than jumping erratically across the chip.
MATHEMATICAL_FORMULATION: Let R_k = {qubits of gates executed in the last k steps}. Define chain_bonus(g) = β if {q1,q2} ∩ R_k ≠ ∅, else 1. H = max_decay × [Σ_{g∈F} chain_bonus(g) × d(Q1,Q2) / |F| + W × Σ_{g∈E} chain_bonus(g) × d(Q1,Q2) / (|E| × layer_factor)]
WHY_NOVEL: No existing routing cost function (SABRE, qBraid, qlosure) explicitly rewards temporal chain continuity. This models the practical asymmetry between "cold" routing (qubit has not been touched recently) and "warm" routing (qubit is already in motion). It adds a stateful, history-dependent dimension absent from all purely static distance functions.
NOVELTY_SCORE: 8
PROBABILITY_SCORE: 7
EFFORT_SCORE: 7
AVERAGE_SCORE: 7.3
STATUS: KEPT

IDEA_NAME: Resistance-Weighted Shortest Path Cost (RWSPC)
DESCRIPTION: Replace hop-count distance d(Q1,Q2) with a resistance-weighted path distance rw_dist(Q1,Q2). Walk the shortest path between Q1 and Q2 on the coupling graph and, for each edge e=(u,v) along that path, add the local edge resistance r(e) = 1 / min(deg(u), deg(v)). Low-degree nodes (bridges, leaves in heavy-hex topology) contribute higher resistance per hop, making paths through topological bottlenecks naturally more expensive — without the instability of full pseudoinverse computation (unlike ERCRC).
MATHEMATICAL_FORMULATION: r(u,v) = 1 / min(deg(u), deg(v)). rw_dist(Q1,Q2) = min over all shortest paths P: Σ_{(u,v)∈P} r(u,v). H = max_decay × [Σ_{g∈F} rw_dist(Q1,Q2) × (deps_g+1) / |F| + W × Σ_{g∈E} rw_dist(Q1,Q2) × (deps_g+1) / (|E| × layer_factor)]
WHY_NOVEL: Unlike ERCRC (full Laplacian pseudoinverse — globally unstable, in NOT-TO-TEST list), RWSPC uses only local structural information (node degrees along the path). Unlike hop-count, it captures bottleneck structure. Unlike GBAC (vertex cut — expensive), it uses a fast, stable approximation computed in O(path_length) per gate. Combines topological awareness with implementation simplicity.
NOVELTY_SCORE: 7
PROBABILITY_SCORE: 7
EFFORT_SCORE: 8
AVERAGE_SCORE: 7.3
STATUS: KEPT
ELIMINATION_REASON: N/A

IDEA_NAME: Lyapunov Power Law Cost (LPLC)
DESCRIPTION: Replace the linear distance penalty d with a super-linear power d^p where p ∈ (1, 2). This function has a well-known theoretical property: it is a Lyapunov function for the routing dynamical system, guaranteeing that any SWAP strictly reducing a qubit pair's distance yields strict cost decrease. The key insight is that p=1 (linear) creates flat gradients for large distances and p=2 (squared) over-penalizes far pairs. The fractional power p=1.5 (or tunable) provides a steeper-than-linear but sub-quadratic penalty, strongly prioritizing near-adjacent pairs without exploding for far pairs.
MATHEMATICAL_FORMULATION: H = max_decay × [Σ_{g∈F} (deps_g+1) × d(Q1,Q2)^p / |F| + W × Σ_{g∈E} (deps_g+1) × d(Q1,Q2)^p / (|E| × layer_factor)], where p ∈ (1, 2) is a fixed hyperparameter (e.g., p=1.5). Convergence guaranteed: ΔH < 0 whenever d(Q1,Q2) → d(Q1,Q2)−1.
WHY_NOVEL: APWC (in NOT-TO-TEST list) used d²+βd⁴ — a polynomial combination that does not converge due to the dominant d⁴ term creating runaway penalties. LPLC uses a single fractional power that is: (1) provably a Lyapunov function, (2) differentiable everywhere, (3) tunable with one parameter, and (4) orders of magnitude simpler. No existing quantum routing cost function uses fractional power distance penalties with formal convergence guarantees.
NOVELTY_SCORE: 7
PROBABILITY_SCORE: 7
EFFORT_SCORE: 8
AVERAGE_SCORE: 7.3
STATUS: KEPT
ELIMINATION_REASON: N/A

IDEA_NAME: Temporal Coupling Coefficient Cost (TCCC)
DESCRIPTION: In the baseline, front-layer and extended-layer contributions are combined additively with a fixed weight W. TCCC instead computes a dynamic weight W_g for each extended-layer gate g_e based on its "temporal coupling" to front-layer gates: if g_e shares a qubit with a front-layer gate g_f, their routing is temporally coupled (routing g_f will also help g_e). The extended layer weight for g_e is scaled by max_{g_f ∈ F} coupling(g_f, g_e), where coupling = 1 if they share a qubit, 0.5 if they share an adjacent qubit in the DAG, 0 otherwise. This makes the extended layer contribution context-sensitive rather than uniform.
MATHEMATICAL_FORMULATION: coupling(g_f, g_e) = 1 if {q1,q2}_{g_f} ∩ {q1,q2}_{g_e} ≠ ∅, else 0.5 if g_e is a direct successor of g_f, else 0. tc(g_e) = max_{g_f∈F} coupling(g_f, g_e). H = max_decay × [F_cost/|F| + W × Σ_{g_e∈E} tc(g_e) × d(Q1,Q2) / (|E| × layer_factor)]
WHY_NOVEL: All existing cost functions (SABRE, qlosure, LOOKAHEAD) treat the extended layer uniformly or with a fixed layer-index decay. TCCC introduces gate-pair-specific coupling between layers, making extended-layer contributions selective: only extended-layer gates that are temporally coupled to front-layer gates receive significant weight. This prevents the extended layer from "diluting" front-layer signals with irrelevant long-range gates.

IDEA_NAME: Inverse Path Density Cost (IPDC)
DESCRIPTION: For each gate pair (Q1, Q2) at hop distance d, count the number of distinct shortest paths π(Q1,Q2) in the coupling graph. Gates where only one shortest path exists (π=1) have no routing flexibility — any congestion on that path forces a detour. Gates with many shortest paths (π≫1) can be routed flexibly. The cost weights each gate by d/log(1 + π(Q1,Q2)): a pair with distance 3 and π=1 costs 3/log2 ≈ 4.3; the same distance with π=7 costs 3/log8 = 1.0. This naturally prioritizes topologically constrained pairs.
MATHEMATICAL_FORMULATION: π(Q1,Q2) = number of distinct shortest paths in coupling graph G (precomputed via BFS count). cost_g = d(Q1,Q2) / log(1 + π(Q1,Q2)). H = max_decay × [Σ_{g∈F} (deps_g+1) × cost_g / |F| + W × Σ_{g∈E} (deps_g+1) × cost_g / (|E| × layer_factor)]
WHY_NOVEL: Path diversity has never been used as a routing cost signal. RPDC (a weaker variant) uses only 1/log(1+π) as a pure weight; IPDC combines path diversity multiplicatively with distance into a single unified cost term. Unlike GBAC (vertex cut — convergence issues) and ECAC (edge load — in NOT-TO-TEST), IPDC uses a static precomputed metric that integrates cleanly into the standard cost formula with guaranteed convergence.
NOVELTY_SCORE: 8
PROBABILITY_SCORE: 7
EFFORT_SCORE: 6
AVERAGE_SCORE: 7.0

IDEA_NAME: Front Layer Parallelism Reward Cost (FLPRC)
DESCRIPTION: After applying a candidate SWAP(a,b) to the temporary mapping, count how many front-layer gates become simultaneously executable (i.e., their two virtual qubits are now adjacent in the coupling graph). Call this parallelism_gain(SWAP). A SWAP that makes 2 gates executable simultaneously is worth twice as much as one that enables only 1. The decay parameter is replaced by an adaptive term that rewards parallelism: decay_adj = max_decay / (1 + α × parallelism_gain). This makes the cost lower (better) for SWAPs that unlock more parallel execution.
MATHEMATICAL_FORMULATION: exec_count(SWAP) = |{g ∈ F : d(Q1_g, Q2_g) = 1 after SWAP}|. decay_adj = max_decay / (1 + α × exec_count(SWAP)). H = decay_adj × [Σ_{g∈F} (deps_g+1) × d(Q1,Q2) / |F| + W × Σ_{g∈E} (deps_g+1) × d(Q1,Q2) / (|E| × layer_factor)]
WHY_NOVEL: Existing cost functions minimize the SUM of distances but never explicitly maximize the number of simultaneously executable gates after a SWAP. SABRE and qlosure use decay as a fixed penalty; FLPRC makes decay adaptive and tied to parallelism gain. This directly optimizes for circuit depth reduction (the true objective) rather than distance reduction as a proxy. No existing routing heuristic uses parallelism gain as a cost modulator.

PROBABILITY_SCORE: 7

IDEA_NAME: SWAP Cascading Displacement Cost (SCDC)
DESCRIPTION: When a candidate SWAP(a,b) is applied, it physically displaces the qubits occupying positions a and b. This displacement affects ALL active routing paths, not just the gate currently being served. For every gate g in F∪E whose shortest routing path passes through qubit a or b, compute the change in shortest-path distance after the SWAP. Sum positive changes (displacement penalty) and subtract negative changes (displacement benefit). This is the first cost function to model the full ripple effect of a SWAP across all concurrent routing needs.
MATHEMATICAL_FORMULATION: Δd_g(SWAP) = d_after(Q1_g, Q2_g) - d_before(Q1_g, Q2_g) after applying SWAP(a,b). ripple(SWAP) = Σ_{g∈F∪E} w_g × Δd_g(SWAP), where w_g = (deps_g+1)/layer_factor_g. H = max_decay × (standard_distance_cost + λ × ripple(SWAP))
WHY_NOVEL: All existing routing cost functions (SABRE, LOOKAHEAD, qlosure) evaluate a candidate SWAP only by its effect on the distance of gates in F and E. SCDC evaluates the SWAP by its net effect on all distances simultaneously — rewarding SWAPs that help many gates while penalizing SWAPs that help one gate but worsen many others. This is the routing equivalent of "look before you leap" at the system level.
NOVELTY_SCORE: 8
PROBABILITY_SCORE: 7
EFFORT_SCORE: 6
AVERAGE_SCORE: 7.0
STATUS: KEPT
ELIMINATION_REASON: N/A

IDEA_NAME: Virtual Neighbor Alignment Cost (VNAC)
DESCRIPTION: For a gate (q1,q2) mapped to physical (Q1,Q2), q1 also interacts with other virtual qubits v_1,...,v_k in future gates (its "virtual neighborhood"). These virtual neighbors are currently mapped to physical qubits P_1,...,P_k. The "alignment" of Q1 is the fraction of its physical neighbors N(Q1) that are currently occupied by virtual neighbors of q1: alignment(Q1) = |N(Q1) ∩ {P_1,...,P_k}| / |N(Q1)|. High alignment means Q1 is already well-positioned for all future interactions with q1's partners. Weight gate costs by 1 - min(alignment(Q1), alignment(Q2)).
MATHEMATICAL_FORMULATION: vneigh(q) = {P_{q'}: q' ∈ future_interactions(q), P_{q'} is physical location of q'}. align(Q,q) = |N(Q) ∩ vneigh(q)| / max(1, |N(Q)|). w_g = 1 - min(align(Q1,q1), align(Q2,q2)). H = max_decay × [Σ_{g∈F} w_g × d(Q1,Q2) / |F| + W × Σ_{g∈E} w_g × d(Q1,Q2) / (|E| × layer_factor)]
WHY_NOVEL: Existing cost functions consider only the current gate pair's distance. VNAC considers whether the physical neighborhood of each qubit is optimally populated for ALL its future interactions simultaneously. This is a second-order criterion: even if d(Q1,Q2)=2 for the current gate, if Q1's physical neighbors are all "wrong" for future gates, routing is globally poor. This holistic alignment concept has no precedent in quantum routing literature.
NOVELTY_SCORE: 9
PROBABILITY_SCORE: 6
EFFORT_SCORE: 6
AVERAGE_SCORE: 7.0

IDEA_NAME: Interaction Urgency Decay Cost (IUDC)
DESCRIPTION: For each virtual qubit pair (q1,q2) with pending gates, define their residual interaction frequency rf(q1,q2) = number of remaining (not yet executed) 2-qubit gates between q1 and q2. Weight each gate's distance contribution by rf(q1,q2) normalized by the maximum residual frequency in the circuit. High-frequency pairs are urgently needed throughout the circuit; routing them closer early pays dividends repeatedly. As gates execute, rf decreases, automatically de-prioritizing pairs that have been serviced. This creates a self-updating urgency signal.
MATHEMATICAL_FORMULATION: rf(q1,q2) = |{remaining gates g : {q1,q2} = {access2q(g)}}|. rf_max = max over all active pairs. urgency_g = rf(q1_g, q2_g) / (rf_max + 1). H = max_decay × [Σ_{g∈F} (1 + urgency_g) × d(Q1,Q2) / |F| + W × Σ_{g∈E} (1 + urgency_g) × d(Q1,Q2) / (|E| × layer_factor)]
WHY_NOVEL: The baseline uses dag_dependencies_count (predecessors) as a weight, measuring past history. IUDC uses residual future interaction frequency, measuring forward-looking pressure. RLPPC (in repo) uses load-proportional priority; IUDC specifically weights by the pair-level interaction frequency — a finer-grained signal than total qubit load. The self-updating nature of rf creates a routing algorithm that naturally adapts to circuit progress without manual tuning.
NOVELTY_SCORE: 7
PROBABILITY_SCORE: 7
EFFORT_SCORE: 7
AVERAGE_SCORE: 7.0
STATUS: KEPT

IDEA_NAME: Qubit Scheduling Conflict Cost (QSCC)
DESCRIPTION: Each physical qubit Q is a shared routing resource. Multiple gates in F∪E may need to route through Q as an intermediate step. Define conflict(Q) = number of gate pairs (g1,g2) in F∪E such that the shortest routing path for g1 AND for g2 both pass through Q. A qubit with high conflict is a routing bottleneck. Weight each gate's distance by the product of conflicts of its two physical qubits: gates routed through high-conflict qubits are more expensive. This penalizes routing plans that route everything through the same bottleneck qubit.
MATHEMATICAL_FORMULATION: path_set(g) = set of intermediate physical qubits on the shortest path from Q1_g to Q2_g. conflict(Q) = |{g∈F∪E: Q ∈ path_set(g)}|. conflict_weight(g) = log(1 + conflict(Q1_g)) × log(1 + conflict(Q2_g)). H = max_decay × [Σ_{g∈F} conflict_weight(g) × d(Q1,Q2) / |F| + W × Σ_{g∈E} conflict_weight(g) × d(Q1,Q2) / (|E| × layer_factor)]
WHY_NOVEL: ECAC (NOT-TO-TEST) penalizes edges; QSCC penalizes intermediate vertices (qubits). CRIC (NOT-TO-TEST) counts path intersections per SWAP edge; QSCC aggregates vertex-level conflict across the entire routing plan and uses it as a gate weight (not as a SWAP penalty). The logarithmic conflict weight prevents runaway penalties while preserving ranking information. No prior routing cost function uses vertex-level routing conflict as a gate weight.
NOVELTY_SCORE: 8
PROBABILITY_SCORE: 6
EFFORT_SCORE: 7

IDEA_NAME: Gate Criticality Vector Cost (GCVC)
DESCRIPTION: Instead of scalar gate weights, represent each gate's urgency as a 3-dimensional criticality vector c_g = (depth_rank_g, successor_count_g, qubit_load_g), where depth_rank is the topological rank in the DAG (normalized), successor_count is the number of direct successors (normalized), and qubit_load is the total remaining interactions for both qubits combined (normalized). Project this vector onto a fixed analytical weight vector w = (w1, w2, w3) (e.g., w = (0.5, 0.3, 0.2)) to get a scalar urgency. This multi-factor urgency replaces the single dep_count weight in the baseline.
MATHEMATICAL_FORMULATION: depth_rank_g = topological_depth(g) / max_depth. succ_g = successors(g) / max_successors. load_g = (remaining_interactions(q1) + remaining_interactions(q2)) / max_load. urgency_g = w1×depth_rank_g + w2×succ_g + w3×load_g. H = max_decay × [Σ_{g∈F} urgency_g × d(Q1,Q2) / |F| + W × Σ_{g∈E} urgency_g × d(Q1,Q2) / (|E| × layer_factor)]
WHY_NOVEL: SCWC (repo) uses only successor count. NIPC (repo) uses qubit load. CPGUC (NOT-TO-TEST) uses critical path length. GCVC combines all three into a unified vector weight with analytical projection, allowing the algorithm to simultaneously consider depth, fan-out, and load. The relative weighting vector w is interpretable and tunable, and the multi-dimensional nature of urgency is conceptually new in quantum routing.
NOVELTY_SCORE: 8
PROBABILITY_SCORE: 6

AVERAGE_SCORE: 7.0

IDEA_NAME: Distance Stagnation Penalty Cost (DSPC)
DESCRIPTION: For each virtual qubit pair (q1,q2) with a pending gate, track stagnation_count(q1,q2) = number of consecutive routing steps during which d(Q1,Q2) has not decreased. When stagnation exceeds a threshold τ, exponentially increase the urgency weight for that pair: penalty = γ^max(0, stagnation-τ), with γ > 1. This prevents the algorithm from indefinitely deferring difficult routing pairs — a key failure mode of greedy distance-sum methods. When d decreases, stagnation resets to 0.
MATHEMATICAL_FORMULATION: stag(q1,q2) ← stag(q1,q2)+1 if d unchanged, else 0. stag_weight(g) = γ^max(0, stag(q1_g,q2_g) - τ), γ=1.5, τ=3 (tunable). H = max_decay × [Σ_{g∈F} stag_weight(g) × (deps_g+1) × d(Q1,Q2) / |F| + W × Σ_{g∈E} stag_weight(g) × (deps_g+1) × d(Q1,Q2) / (|E| × layer_factor)]
WHY_NOVEL: PRDC (repo) modifies the decay parameter globally based on qubit usage frequency. DSPC specifically tracks per-pair stagnation and applies exponential urgency boost only when a pair has been neglected. This is fundamentally different: it is reactive (triggered by stagnation events), pair-specific (not qubit-level), and exponential (not polynomial). It models the practical failure mode of greedy routing and adds a convergence-enforcing mechanism absent from all prior cost functions.

IDEA_NAME: Topological Betweenness Penalty Cost (TBPC)
DESCRIPTION: Precompute the betweenness centrality BC(Q) for each physical qubit Q in the coupling graph. Qubits with high BC are topological "relay hubs" — many shortest paths pass through them. When a gate requires routing through such a hub, future gates will also need that hub, creating congestion. Penalize gate distances by weighting them with the betweenness centrality of the physical qubits involved: gates assigned to or routing through high-BC qubits get higher cost, incentivizing the algorithm to place interacting qubit pairs near each other rather than relying on hub qubits.
MATHEMATICAL_FORMULATION: BC(Q) = Σ_{s≠Q≠t} σ(s,t|Q)/σ(s,t) normalized to [0,1]. bc_weight(g) = 1 + β × max(BC(Q1_g), BC(Q2_g)). H = max_decay × [Σ_{g∈F} bc_weight(g) × d(Q1,Q2) / |F| + W × Σ_{g∈E} bc_weight(g) × d(Q1,Q2) / (|E| × layer_factor)]
WHY_NOVEL: Betweenness centrality has been used in qubit allocation/placement but never in the routing cost function itself. Unlike CGCAC (eigenvector centrality — similar but uses global influence not path-through), TBPC specifically uses betweenness, which is the exact measure of how often a qubit appears on routing paths. A coupling graph hub qubit is a finite resource; BC precisely quantifies its routing load capacity, making TBPC theoretically grounded for congestion avoidance.

IDEA_NAME: Dual-Layer Tension Cost (DLTC)
DESCRIPTION: Compute the "routing tension" between front layer and extended layer: for each candidate SWAP, compute the front-layer gradient (how much the SWAP reduces total front-layer distance) and the extended-layer gradient. If these two gradients point in opposite directions (tension), the extended layer is actively misleading the front layer. Scale W dynamically: W_tension = W × max(0, cosine_similarity(grad_F, grad_E) + 1)/2 ∈ [0, W]. When tension is high (cos ≈ -1), W_tension ≈ 0 (ignore extended layer). When tension is low (cos ≈ +1), W_tension = W (full extended layer weight).
MATHEMATICAL_FORMULATION: grad_F(SWAP) = Σ_{g∈F} [d_before(Q1,Q2) - d_after(Q1,Q2)]. grad_E(SWAP) = Σ_{g∈E} [d_before(Q1,Q2) - d_after(Q1,Q2)]. cos_sim = (grad_F · grad_E)/(|grad_F| × |grad_E| + ε). W_dyn = W × (cos_sim + 1)/2. H = max_decay × [F_cost/|F| + W_dyn × E_cost/|E|]
WHY_NOVEL: Every existing cost function combines front and extended layers with a fixed weight W. DLTC makes W dynamically adaptive per SWAP based on whether the extended layer agrees or conflicts with the front layer. When the lookahead is misleading (opposite gradient), it is automatically silenced. This is inspired by multi-objective optimization theory and has no analog in quantum routing literature.
NOVELTY_SCORE: 9
PROBABILITY_SCORE: 6
EFFORT_SCORE: 5
AVERAGE_SCORE: 6.7
STATUS: KEPT
ELIMINATION_REASON: N/A

IDEA_NAME: Persistent Homology Routing Cost (PHRC)
DESCRIPTION: Use topological data analysis to compute the persistence diagram of the qubit interaction filtration. Penalize mappings where interaction cycles have high persistence (indicating routing loops). Use bottleneck distance between persistence diagrams as routing cost.
MATHEMATICAL_FORMULATION: PD(K_t) = {(birth_i, death_i)} from Vietoris-Rips filtration on qubit interaction graph. Cost = W_bottleneck(PD_virtual, PD_physical).
WHY_NOVEL: First application of algebraic topology to routing cost functions.
NOVELTY_SCORE: 10
PROBABILITY_SCORE: 3
EFFORT_SCORE: 2
AVERAGE_SCORE: 5.0
STATUS: ELIMINATED
ELIMINATION_REASON: Persistent homology computation is O(n³) per step; the cost signal does not provide a clear decreasing gradient for the greedy routing algorithm. Filtration-based distances are not aligned with the single-SWAP discrete updates used in routing. Very likely to not converge in the greedy framework.

IDEA_NAME: Virtual-Physical Misalignment Entropy Cost (VPMEC)
DESCRIPTION: Compute the KL divergence between the distribution of virtual qubit interaction distances (in the virtual interaction graph) and the distribution of physical qubit distances (in the current mapping). High KL divergence = poor placement globally. Use this as a circuit-level cost penalizing the overall mapping quality.
MATHEMATICAL_FORMULATION: P_v(d) = empirical distribution of d_virtual(q1,q2) for all gate pairs. P_p(d) = empirical distribution of d_physical(Q1,Q2) under current mapping. Cost = D_KL(P_v || P_p).
WHY_NOVEL: Global information-theoretic placement quality metric.
NOVELTY_SCORE: 8
PROBABILITY_SCORE: 4
EFFORT_SCORE: 5
AVERAGE_SCORE: 5.7
STATUS: ELIMINATED
ELIMINATION_REASON: KL divergence is a global distribution-level metric that provides no directional gradient for individual SWAP selection. Different SWAPs produce tiny changes to the distribution, making the signal-to-noise ratio too low for greedy routing decisions. The metric correlates with placement quality but does not converge as a per-SWAP cost.

IDEA_NAME: Qubit Thermal Equilibrium Cost (QTEC)
DESCRIPTION: Model the coupling graph as a heat bath. Each qubit has "temperature" T(Q) = number of remaining interactions it is involved in. Routing cost = free energy needed to bring interacting qubit pairs to thermal equilibrium: F = Σ_g |T(Q1_g) - T(Q2_g)| × d(Q1,Q2). Minimizing F routes qubits of similar thermal load toward each other.
MATHEMATICAL_FORMULATION: T(Q) = |{remaining gates g : Q ∈ {Q1_g, Q2_g}}|. F(SWAP) = Σ_{g∈F} |T(Q1_g) - T(Q2_g)| × d(Q1,Q2) / |F|.
WHY_NOVEL: Thermodynamic analogy applied to routing urgency.
NOVELTY_SCORE: 7
PROBABILITY_SCORE: 4
EFFORT_SCORE: 5
AVERAGE_SCORE: 5.3
STATUS: ELIMINATED
ELIMINATION_REASON: The thermal equilibrium metaphor does not faithfully model routing: two qubits with identical load T(Q1)=T(Q2) get zero urgency even if d(Q1,Q2)=5 and their gate is in the front layer. The |T(Q1)-T(Q2)| term can vanish for the most urgent gate pairs, causing non-convergence. Temperature equilibration is the wrong objective for SWAP minimization.
