IDEA_NAME: Greedy Weighted Pair-First Adjacent Placement (GWPFAP)
DESCRIPTION: Instead of placing one qubit at a time from a single anchor, this algorithm first sorts all logical qubit pairs by their interaction weight (number of 2Q gates between them). It then processes pairs in descending weight order, placing each high-weight pair directly onto an adjacent hardware edge. By targeting hardware edges (adjacent physical qubit pairs) for the most frequently-interacting logical pairs, the algorithm eliminates SWAPs for those gate pairs entirely — they are adjacent by construction.
ALGORITHMIC_APPROACH:
1. Build interaction weight dict: `w[(q1,q2)] = count of 2Q gates` from `self.access`
2. Sort all pairs by weight descending → `sorted_pairs`
3. `lq_to_phys = {}`, `placed_phys = set()`
4. For each pair `(l1, l2)` in order:
   - If neither placed: find the hardware edge `(p1, p2)` ∈ `self.backend` that minimizes `sum_{lq_placed} w[(l1,lq)] * dist[p1][mapping[lq]] + w[(l2,lq)] * dist[p2][mapping[lq]]`; assign `l1→p1, l2→p2`
   - If `l1` placed to `p1` only: find best unoccupied hardware neighbor `p2` of `p1` by interaction cost; assign `l2→p2`
   - If both placed: skip
5. Fill remaining logical qubits onto remaining physical qubits by hardware degree (descending)
6. Apply bijection enforcement
COLLISION_PREVENTION: Each pair-assignment checks `placed_phys` to ensure no physical qubit is reused. The bijection enforcement via in-place swaps (lines 217–230 of `routing.py`) guarantees strict 1-to-1 mapping over the full `num_qubits` range. No logical qubit is assigned twice since pairs are processed with explicit `if neither/one/both placed` guards.
WHY_NOVEL: All existing methods (SABRE, IFWBAP, random) place qubits individually, one-by-one. GWPFAP places *pairs* as atomic units, directly targeting the hardware adjacency constraint that causes SWAPs. Placing the top-K pairs on hardware edges can make those K×(gate_count) 2Q gates SWAP-free by construction — no existing compiler heuristic treats adjacency as a first-class placement objective.

```python
    for lq, phys in lq_to_phys.items():
        cost += interaction_weight.get((min(l1,lq),max(l1,lq)),0)*self.distance_matrix[p1][phys]
        cost += interaction_weight.get((min(l2,lq),max(l2,lq)),0)*self.distance_matrix[p2][phys]

    if l1_placed and l2_placed: continue

                [p for p in physical_qubits if p not in placed_phys]
        best_p1 = min(cands, key=lambda p: self.distance_matrix[p][p2])
        lq_to_phys[l1] = best_p1; placed_phys.add(best_p1)

remaining_phys = sorted([p for p in physical_qubits if p not in placed_phys],
                         key=lambda p: len(self.backend[p]), reverse=True)
logical_qubits = sorted(set(q for qs in self.access.values() for q in qs))
unplaced = [lq for lq in logical_qubits if lq not in lq_to_phys]
for lq, phys in zip(unplaced, remaining_phys):
```

IDEA_NAME: Fiedler-Vector Bandwidth Minimization Ordering (FBMO)
DESCRIPTION: The graph bandwidth problem asks: find an ordering of nodes such that adjacent (interacting) nodes are close in the ordering. The Fiedler vector (second eigenvector of the normalized graph Laplacian) gives a spectral approximation to this ordering. Independently, the hardware graph can be ordered by BFS distance from its most central node, yielding a "hardware spectrum." Matching the two spectra aligns frequently-interacting logical qubits with nearby physical qubits.
ALGORITHMIC_APPROACH:
1. Build weighted interaction graph Laplacian `L_L` from `self.access` interaction weights
2. Compute Fiedler vector `v_L` of `L_L` using `numpy.linalg.eigh` on the `n_logical × n_logical` submatrix; sort logical qubits by `v_L` value → `ordered_logical`
3. Compute all-pairs BFS distances using `self.distance_matrix`; for each physical qubit compute `mean_dist[p]`; sort physical qubits by `mean_dist` ascending → `ordered_physical` (most central first)
4. Map `ordered_logical[i] → ordered_physical[i]` for all `i`
5. Apply bijection enforcement
COLLISION_PREVENTION: The Fiedler sort yields a permutation of logical qubits; the `mean_dist` sort yields a permutation of physical qubits. Matching by rank index is inherently injective. The bijection enforcement handles any residual conflicts from isolated qubits.
WHY_NOVEL: The Fiedler vector naturally clusters strongly-connected logical qubits together in the ordering (bandwidth minimization). Simultaneously ordering the hardware by centrality places the "core" of the interaction graph onto the "core" of the hardware. This is a purely spectral, globally-coherent approach not found in SABRE, IFWBAP, or any published quantum placement heuristic.

```python
from collections import defaultdict

interaction_weight = defaultdict(float)
logical_qubit_set = set()
for gate, qubits in self.access.items():
    for q in qubits: logical_qubit_set.add(q)
    if len(qubits) == 2:
        key = (min(qubits[0],qubits[1]), max(qubits[0],qubits[1]))
        interaction_weight[key] += 1

logical_qubits = sorted(logical_qubit_set)
n = len(logical_qubits)
lq_idx = {lq: i for i, lq in enumerate(logical_qubits)}
physical_qubits = sorted(self.backend.keys())

if n > 1:
    # Build normalized Laplacian
    W = np.zeros((n, n))
    for (q1, q2), w in interaction_weight.items():
        i, j = lq_idx.get(q1), lq_idx.get(q2)
        if i is not None and j is not None:
            W[i, j] = W[j, i] = w
    D = np.diag(W.sum(axis=1))
    L = D - W
    # Fiedler vector (second smallest eigenvalue)
    eigvals, eigvecs = np.linalg.eigh(L)
    fiedler = eigvecs[:, 1] if n > 1 else eigvecs[:, 0]
    ordered_logical = [logical_qubits[i] for i in np.argsort(fiedler)]
else:
    ordered_logical = logical_qubits

# Order physical qubits by mean BFS distance (ascending = most central first)
def mean_dist(p):
    finite = [self.distance_matrix[p][o] for o in physical_qubits
              if o != p and self.distance_matrix[p][o] != float('inf')]
    return sum(finite)/len(finite) if finite else float('inf')
ordered_physical = sorted(physical_qubits, key=mean_dist)

lq_to_phys = {lq: ordered_physical[i] for i, lq in enumerate(ordered_logical)}
```

IDEA_NAME: Hungarian Algorithm Interaction-Degree Cost Matrix Placement (HIDCMP)
DESCRIPTION: Formulate initial placement as a linear assignment problem. Build a cost matrix `C[l][p]` where `C[l][p]` represents how "mismatched" logical qubit `l` is to physical qubit `p`, based on the ratio of logical interaction degree to physical hardware degree. Use `scipy.optimize.linear_sum_assignment` (Hungarian algorithm) to find the globally-optimal assignment minimizing total cost. This is O(n³) — feasible for up to ~200 qubits.
ALGORITHMIC_APPROACH:
1. Compute `interaction_degree[l]` = weighted degree of logical qubit `l` in interaction graph
2. Compute `hardware_degree[p]` = degree of physical qubit `p` in hardware (available via `self.backend`)
3. Compute `mean_hw_dist[p]` = mean BFS distance from `p` to all other physical qubits
4. Build cost matrix `C[i][j]` for logical index `i` → physical index `j`:
   `C[i][j] = |normalized_interaction_degree[i] - normalized_hw_connectivity[j]| + alpha * mean_hw_dist[j] * interaction_degree[i]`
5. Apply Hungarian via `scipy.optimize.linear_sum_assignment(C)` → optimal assignment
6. Apply bijection enforcement
COLLISION_PREVENTION: The Hungarian algorithm by definition produces a perfect matching on a square matrix (bijection). After padding the cost matrix to `num_qubits × num_qubits` with zero-cost dummy rows/columns for unused physical qubits, the result is always a valid permutation.
WHY_NOVEL: Existing methods are greedy sequential (place one qubit, then next). The Hungarian approach finds a globally-optimal assignment under a degree-correlation cost in O(n³), a fundamentally different paradigm. No SOTA quantum compiler uses the Hungarian algorithm for initial qubit placement.

```python
from collections import defaultdict

interaction_degree = defaultdict(float)
logical_qubit_set = set()
for gate, qubits in self.access.items():
    for q in qubits: logical_qubit_set.add(q)
    if len(qubits) == 2:
        for q in qubits: interaction_degree[q] += 1

logical_qubits = sorted(logical_qubit_set)
physical_qubits = sorted(self.backend.keys())
n_l, n_p = len(logical_qubits), len(physical_qubits)

hw_degree = {p: len(self.backend[p]) for p in physical_qubits}
max_hw_deg = max(hw_degree.values()) or 1
max_int_deg = max(interaction_degree.values(), default=1)

def mean_dist(p):
    finite = [self.distance_matrix[p][o] for o in physical_qubits
              if o != p and self.distance_matrix[p][o] != float('inf')]
    return sum(finite)/len(finite) if finite else float('inf')

# C is n_l × n_p cost matrix
C = np.zeros((n_l, n_p))
for i, lq in enumerate(logical_qubits):
    n_int = interaction_degree[lq] / max_int_deg
    for j, pq in enumerate(physical_qubits):
        n_hw = hw_degree[pq] / max_hw_deg
        C[i, j] = abs(n_int - n_hw) + n_int * mean_dist(pq) / 10.0

row_ind, col_ind = linear_sum_assignment(C)
lq_to_phys = {logical_qubits[i]: physical_qubits[j]
              for i, j in zip(row_ind, col_ind)}
# → apply bijection enforcement
```

IDEA_NAME: Critical Chain Hardware Path Co-Routing (CCHPCR)
DESCRIPTION: The critical path through the 2Q-gate DAG is the bottleneck of the circuit: all routing delays on this path add to the total circuit depth. CCHPCR finds the critical path (longest path weighted by gate count or transitive closure depth), extracts the unique logical qubits along it in order of appearance, then finds a "hardware chain" (longest simple path or BFS-based diameter path in the hardware graph) and co-routes the two chains together. Critical-chain qubits are mapped to hardware chain nodes 1-to-1 in order. Remaining qubits use interaction-weighted BFS expansion.
ALGORITHMIC_APPROACH:
1. Build 2Q-gate DAG from `self.access`: edges = gates, nodes = sequential order
2. Topological sort and compute longest path via DP: `dp[g] = 1 + max(dp[pred] for pred in predecessors)`
3. Backtrack to extract the critical path as an ordered sequence of gates `[g1, g2, ..., gk]`
4. Extract unique logical qubits in order of first appearance on the critical path → `chain_logical`
5. Find hardware diameter path: BFS from most peripheral node, find farthest node, BFS back → `chain_physical`
6. Map `chain_logical[i] → chain_physical[i]` (truncate to min length)
7. Place remaining qubits via interaction-weighted BFS from placed set
8. Apply bijection enforcement
COLLISION_PREVENTION: Chain assignment is sequential with an explicit visited set. BFS expansion uses `placed_phys` exclusion set. Bijection enforcement handles the final injection.
WHY_NOVEL: No existing quantum placement algorithm explicitly targets the DAG critical path for placement. SABRE, IFWBAP, and others treat all gates uniformly. By aligning the critical path of the circuit with a path in the hardware graph, routing overhead on the most time-critical qubit chain is structurally minimized.
NOVELTY_SCORE: 7
PROBABILITY_SCORE: 7

```python
predecessors_2q = defaultdict(set)
successors_2q = defaultdict(set)
schedule = sorted(gates_2q.keys())

            pred_hw[nb] = node; q.append(nb)
chain_physical = []
cur = end2
while cur is not None:
    chain_physical.append(cur); cur = pred_hw.get(cur)

# Step 6: Assign chain
lq_to_phys = {}
placed_phys = set()
for i, lq in enumerate(chain_logical[:len(chain_physical)]):
    lq_to_phys[lq] = chain_physical[i]; placed_phys.add(chain_physical[i])

for g, qubits in self.access.items():

        interaction_neighbors[q1][q2] = interaction_neighbors[q1].get(q2, 0) + 1
        interaction_neighbors[q2][q1] = interaction_neighbors[q2].get(q1, 0) + 1

all_logical = sorted(set(q for qs in self.access.values() for q in qs))
unplaced = [lq for lq in all_logical if lq not in lq_to_phys]
while unplaced:
```

IDEA_NAME: Temporal Layer Exponentially Discounted Interaction Weighting (TLEDIW)
DESCRIPTION: Standard interaction graphs treat gates uniformly. But gates in early DAG layers *must* execute first and cannot benefit from any pre-routing; they are the gates most directly impacted by initial placement. TLEDIW builds a time-discounted interaction graph by computing topological layers and assigning each gate's interaction weight as `w * exp(-λ * layer_index)`. Early gates get higher weight, encouraging their qubit pairs to be placed adjacently. This time-discounted graph then feeds into the standard IFWBAP anchor+BFS placement.
ALGORITHMIC_APPROACH:
1. Build 2Q-gate DAG, compute topological layer index for each gate via BFS
2. Build time-discounted interaction weight: `w_disc[(q1,q2)] += exp(-λ * layer[g])` for each 2Q gate `g` on qubits `(q1,q2)`, with λ typically 0.1–0.5
3. Use time-discounted weights in place of raw counts for all IFWBAP steps: weighted degree → anchor selection → BFS expansion placement cost
4. Apply bijection enforcement
COLLISION_PREVENTION: Identical to IFWBAP — same BFS expansion with `placed_phys` exclusion set and bijection enforcement. Only the weights fed to the algorithm differ.
WHY_NOVEL: All existing placement algorithms (SABRE, IFWBAP, random) ignore the temporal order of gates — they flatten the circuit into a static interaction graph. TLEDIW introduces a temporal axis into the placement objective, recognizing that the *timing* of interactions in the circuit should influence placement. This is analogous to "time-value discounting" in economics applied to quantum circuit structure.

IDEA_NAME: Dual PageRank Rank-Correlation Placement (DPRCP)
DESCRIPTION: PageRank on the weighted logical interaction graph gives each logical qubit an "importance score" based on random-walk centrality — capturing both direct interaction frequency and indirect influence through neighbors. Independently, PageRank on the hardware graph gives each physical qubit a "centrality score" reflecting its random-walk reachability. Matching high-PageRank logical qubits to high-PageRank physical qubits aligns the most globally-important circuit qubits with the most globally-connected hardware nodes.
ALGORITHMIC_APPROACH:
1. Build weighted interaction graph as `networkx.Graph` with edge weight = gate count
2. Compute `pagerank(G_interaction, weight='weight')` → `lq_pr[lq]`
3. Build hardware graph as `networkx.Graph` from `self.backend`
4. Compute `pagerank(G_hardware)` → `pq_pr[pq]`
5. Sort logical qubits by `lq_pr` descending → `ranked_logical`
6. Sort physical qubits by `pq_pr` descending → `ranked_physical`
7. Map `ranked_logical[i] → ranked_physical[i]`
8. Apply bijection enforcement
COLLISION_PREVENTION: Rank-sort yields two permutations; positional assignment by rank index is inherently injective. Bijection enforcement handles isolated logical qubits not appearing in 2Q gates.
WHY_NOVEL: The existing IFWBAP uses weighted degree (local, first-order) and mean BFS distance (crude global metric). PageRank captures multi-hop, iterative, random-walk-based importance — a fundamentally richer centrality measure. Matching *two* PageRank distributions (interaction vs. hardware) is not used in any quantum compilation literature.
NOVELTY_SCORE: 7

IDEA_NAME: Louvain Community Detection Cluster-to-Subgraph Hierarchical Mapping (LCDCSHM)
DESCRIPTION: Apply Louvain community detection to the weighted interaction graph, partitioning logical qubits into cohesive interaction clusters. Simultaneously, identify dense subgraphs of the hardware by greedy clique/community expansion. Match interaction communities to hardware sub-regions hierarchically by intra-community edge density. Within each community-subgraph pair, apply IFWBAP-style local BFS placement. This two-level hierarchical approach first gets the "neighborhoods right" at the community level, then optimizes individual placement within each community.
ALGORITHMIC_APPROACH:
1. Build weighted interaction graph as `networkx.Graph`
2. Run `networkx.algorithms.community.louvain_communities(G_int, weight='weight')` → `communities_logical` (list of sets)
3. Compute intra-community density for each community `C`: `density(C) = sum of edge weights within C / |C|^2`
4. Sort communities by density descending
5. For hardware: find dense subgraphs via greedy expansion from high-degree nodes, creating hardware "regions" of matching sizes
6. Match community[i] → hardware_region[i] by density rank
7. Within each matched pair (community, region): run IFWBAP anchor+BFS restricted to that region
8. Apply bijection enforcement
COLLISION_PREVENTION: Each community and each hardware region is disjoint. Within-community IFWBAP uses region-restricted `placed_phys` sets. Final bijection enforcement resolves any residual issues.
WHY_NOVEL: A two-level hierarchical placement strategy. No existing quantum compiler applies graph community detection as a first step to group logical qubits before placement. Community structure captures the natural "module" structure of quantum algorithms (e.g., QFT butterfly patterns, QAOA layers) that flat methods miss entirely.
NOVELTY_SCORE: 8
PROBABILITY_SCORE: 7
EFFORT_SCORE: 6
FEASIBILITY_SCORE: 9
AVERAGE_SCORE: 7.5

**Reference code (core, requires `pip install python-louvain` or `networkx>=3.1`):**

```python
import networkx as nx
from networkx.algorithms.community import louvain_communities
from collections import defaultdict

G_int = nx.Graph()
logical_qubit_set = set()
for gate, qubits in self.access.items():
    for q in qubits: logical_qubit_set.add(q)
    if len(qubits) == 2:
        q1, q2 = qubits
        if G_int.has_edge(q1, q2): G_int[q1][q2]['weight'] += 1
        else: G_int.add_edge(q1, q2, weight=1)

G_hw = nx.Graph([(p, nb) for p, nbs in self.backend.items() for nb in nbs])

# Community detection on interaction graph
if G_int.number_of_edges() > 0:
    comm_logical = louvain_communities(G_int, weight='weight', seed=42)
else:
    comm_logical = [set(logical_qubit_set)]

# Greedy hardware region detection (expand from high-degree seed)
hw_degree = {p: len(self.backend[p]) for p in self.backend}
used_hw = set()
hw_regions = []
for comm in sorted(comm_logical, key=len, reverse=True):
    seed = max((p for p in G_hw.nodes() if p not in used_hw),
               key=lambda p: hw_degree[p], default=None)
    if seed is None: break
    region = {seed}; queue = list(self.backend[seed])
    while len(region) < len(comm) and queue:
        node = queue.pop(0)
        if node not in used_hw and node not in region:
            region.add(node)
            queue.extend(nb for nb in self.backend[node] if nb not in region)
    hw_regions.append(region); used_hw.update(region)

# Within each (community, region) pair: IFWBAP-style local BFS
lq_to_phys = {}
placed_phys = set()
for comm, region in zip(comm_logical, hw_regions):
    region_list = sorted(region)
    # Anchor = max interaction degree in community
    anchor_lq = max(comm, key=lambda lq: G_int.degree(lq, weight='weight'))
    # Anchor physical = most central in region
    anchor_phys = min(region_list, key=lambda p:
        sum(self.distance_matrix[p][o] for o in region_list if o != p) / max(len(region_list)-1,1))
    lq_to_phys[anchor_lq] = anchor_phys; placed_phys.add(anchor_phys)
    for lq in comm:
        if lq == anchor_lq: continue
        cands = [p for p in region_list if p not in placed_phys]
        if not cands: cands = [p for p in sorted(self.backend.keys()) if p not in placed_phys]
        best_p = min(cands, key=lambda p: sum(
            G_int.get_edge_data(lq, pl, {}).get('weight', 0) * self.distance_matrix[p][pp]
            for pl, pp in lq_to_phys.items()))
        lq_to_phys[lq] = best_p; placed_phys.add(best_p)
# → fill remaining + bijection enforcement
```

IDEA_NAME: Betweenness Centrality Bridge-to-Bridge Dual Rank Matching (BCBDRM)
DESCRIPTION: Betweenness centrality measures how often a node lies on shortest paths between other nodes. A logical qubit with high betweenness in the interaction graph is a "bridge" connecting multiple interacting clusters — it mediates many indirect interactions. A physical qubit with high betweenness in the hardware graph is also a bridge connecting multiple hardware regions. BCBDRM matches logical bridges to hardware bridges, preserving the "mediation structure" of the circuit onto the hardware topology.
ALGORITHMIC_APPROACH:
1. Build weighted interaction graph; compute `networkx.betweenness_centrality(G_int, weight='weight')`
2. Build hardware graph; compute `networkx.betweenness_centrality(G_hw)`
3. Sort logical qubits by betweenness descending → `ranked_logical`
4. Sort physical qubits by betweenness descending → `ranked_physical`
5. Map `ranked_logical[i] → ranked_physical[i]`
6. Apply bijection enforcement
COLLISION_PREVENTION: Same as DPRCP — positional rank assignment is injective by construction.
WHY_NOVEL: Betweenness centrality captures fundamentally different graph properties than degree or PageRank — it measures "bridge" roles. The hypothesis is that logical qubits that bridge interaction clusters (and thus need to "route" information between them) should be placed on hardware qubits that can efficiently route SWAPs across the topology. This "bridge-to-bridge" mapping is not used in any existing placement algorithm.
NOVELTY_SCORE: 7
PROBABILITY_SCORE: 6
EFFORT_SCORE: 8
FEASIBILITY_SCORE: 10
AVERAGE_SCORE: 7.8

IDEA_NAME: Qubit Lifetime × Interaction Importance Bipartite Hungarian Matching (QLIBHM)
DESCRIPTION: Each logical qubit has two orthogonal properties: (1) its **lifetime** — how many DAG layers it actively participates in, from first to last gate — and (2) its **interaction importance** — total weighted degree. The product `lifetime × interaction_degree` gives a "sustained importance" score. On the hardware side, high-degree physical qubits provide more routing flexibility over time. QLIBHM builds a cost matrix that jointly minimizes the mismatch between sustained importance and hardware flexibility, solved optimally via the Hungarian algorithm.
ALGORITHMIC_APPROACH:
1. Compute topological layer index for each gate via BFS on the full DAG (using `self.access`)
2. For each logical qubit `lq`, compute: `first_layer[lq]`, `last_layer[lq]`, `lifetime[lq] = last_layer - first_layer + 1`
3. Compute `interaction_degree[lq]` = total gate count involving `lq`
4. Compute `sustained_importance[lq] = lifetime[lq] * interaction_degree[lq]`
5. Compute `hw_flexibility[p] = hardware_degree[p] + 1 / (mean_bfs_dist[p] + 1)`
6. Build cost matrix: `C[i][j] = (normalized_sustained_importance[i] - normalized_hw_flexibility[j])^2`
7. Solve via `scipy.optimize.linear_sum_assignment(C)`
8. Apply bijection enforcement
COLLISION_PREVENTION: Hungarian algorithm produces a perfect bijection. Padding to `num_qubits × num_qubits` ensures all physical qubits are considered.
WHY_NOVEL: "Qubit lifetime" — how long a qubit remains active in the circuit — has not been used as a placement criterion in any published work. Long-lived qubits need persistent hardware connectivity; short-lived qubits can be parked at the periphery. This temporal persistence metric combined with hardware flexibility via Hungarian optimization is fundamentally novel.
NOVELTY_SCORE: 8
PROBABILITY_SCORE: 6
EFFORT_SCORE: 7
FEASIBILITY_SCORE: 10
AVERAGE_SCORE: 7.8

**Reference code (core):**
```python
import numpy as np
from scipy.optimize import linear_sum_assignment
from collections import defaultdict, deque

# Step 1: Topological layers from full DAG
predecessors_full = defaultdict(set)
successors_full = defaultdict(set)
schedule = sorted(self.access.keys())
last_write = {}
for g in schedule:
    for q in self.access[g]:
        if q in last_write:
            pred = last_write[q]
            successors_full[pred].add(g); predecessors_full[g].add(pred)
        last_write[q] = g

layer = {}
bfs_q = deque([g for g in schedule if not predecessors_full[g]])
for g in bfs_q: layer.setdefault(g, 0)
while bfs_q:
    g = bfs_q.popleft()
    for s in successors_full[g]:
        new_l = layer[g] + 1
        if layer.get(s, -1) < new_l: layer[s] = new_l; bfs_q.append(s)

# Step 2: Lifetime and interaction degree per logical qubit
first_layer = {}; last_layer = {}; interaction_degree = defaultdict(float)
for g, qubits in self.access.items():
    l = layer.get(g, 0)
    for q in qubits:
        first_layer[q] = min(first_layer.get(q, l), l)
        last_layer[q] = max(last_layer.get(q, l), l)
        interaction_degree[q] += 1

logical_qubit_set = set(q for qs in self.access.values() for q in qs)
logical_qubits = sorted(logical_qubit_set)
physical_qubits = sorted(self.backend.keys())

sustained = {lq: (last_layer.get(lq,0) - first_layer.get(lq,0) + 1) * interaction_degree[lq]
             for lq in logical_qubits}
max_sus = max(sustained.values(), default=1)

def mean_dist(p):
    f = [self.distance_matrix[p][o] for o in physical_qubits
         if o != p and self.distance_matrix[p][o] != float('inf')]
    return sum(f)/len(f) if f else float('inf')

hw_flex = {p: len(self.backend[p]) + 1.0/(mean_dist(p)+1) for p in physical_qubits}
max_flex = max(hw_flex.values(), default=1)

n_l, n_p = len(logical_qubits), len(physical_qubits)
C = np.zeros((n_l, n_p))
for i, lq in enumerate(logical_qubits):
    ns = sustained[lq] / max_sus
    for j, pq in enumerate(physical_qubits):
        nf = hw_flex[pq] / max_flex
        C[i, j] = (ns - nf) ** 2

row_ind, col_ind = linear_sum_assignment(C)
lq_to_phys = {logical_qubits[i]: physical_qubits[j]
              for i, j in zip(row_ind, col_ind)}
# → apply bijection enforcement
```

IDEA_NAME: DAG Peak-Density Bottleneck Layer Compact Placement (DPDBCP)
DESCRIPTION: The DAG layer with the maximum number of simultaneous 2Q gate interactions is the circuit's "bottleneck layer" — the moment with the highest parallel routing demand. If the qubits active in this layer are scattered across the hardware, routing congestion is maximal at this critical moment. DPDBCP identifies this bottleneck layer, extracts its active qubit set, then places these qubits onto the densest connected hardware subgraph, ensuring maximum hardware connectivity precisely at the circuit's most demanding moment.
ALGORITHMIC_APPROACH:
1. Compute topological layers for all 2Q gates
2. For each layer `l`, count `density[l]` = number of 2Q gates in layer `l`
3. Identify `peak_layer = argmax(density)`; extract `bottleneck_qubits` = unique qubits in gates at `peak_layer`
4. Find dense hardware subgraph of size `|bottleneck_qubits|` by greedy expansion from highest-degree node: seed → add neighbor with max edges within growing subgraph
5. Within the bottleneck subgraph, use IFWBAP anchor+BFS to assign `bottleneck_qubits`
6. For remaining qubits: standard interaction-weighted BFS expansion from placed set
7. Apply bijection enforcement
COLLISION_PREVENTION: Bottleneck subgraph assignment uses explicit occupancy checks. Remaining BFS uses `placed_phys` exclusion. Bijection enforcement provides final guarantee.
WHY_NOVEL: No existing placement algorithm targets the circuit's *most parallel moment* (peak-density layer) specifically. Ensuring the hardware is maximally compact at the bottleneck moment directly minimizes routing overhead exactly when it matters most. This is a novel application of "temporal bottleneck identification" to hardware-aware placement.
NOVELTY_SCORE: 8
PROBABILITY_SCORE: 7
EFFORT_SCORE: 7
FEASIBILITY_SCORE: 9
AVERAGE_SCORE: 7.8

**Reference code (core):**
```python
from collections import defaultdict, deque
import math

gates_2q = {g: qubits for g, qubits in self.access.items() if len(qubits) == 2}
schedule_2q = sorted(gates_2q.keys())

# Compute topological layers
predecessors = defaultdict(set); successors = defaultdict(set)
last_on = {}
for g in schedule_2q:
    for q in gates_2q[g]:
        if q in last_on:
            pred = last_on[q]
            successors[pred].add(g); predecessors[g].add(pred)
        last_on[q] = g

layer = {}
bfs_q = deque([g for g in schedule_2q if not predecessors[g]])
for g in bfs_q: layer.setdefault(g, 0)
while bfs_q:
    g = bfs_q.popleft()
    for s in successors[g]:
        new_l = layer[g] + 1
        if layer.get(s, -1) < new_l: layer[s] = new_l; bfs_q.append(s)

# Find peak density layer
layer_counts = defaultdict(int)
for g in schedule_2q: layer_counts[layer.get(g, 0)] += 1
if not layer_counts:
    # fallback to trivial
    self.mapping_dict = list(range(self.num_qubits))
    self.reverse_mapping_dict = list(range(self.num_qubits))
    return
peak_layer = max(layer_counts, key=layer_counts.get)
bottleneck_qubits = list({q for g in schedule_2q
                          if layer.get(g, 0) == peak_layer
                          for q in gates_2q[g]})

# Find dense hardware subgraph of size |bottleneck_qubits|
k = len(bottleneck_qubits)
physical_qubits = sorted(self.backend.keys())
hw_degree = {p: len(self.backend[p]) for p in physical_qubits}
seed = max(physical_qubits, key=lambda p: hw_degree[p])
dense_subgraph = {seed}
candidates = sorted(self.backend[seed], key=lambda p: hw_degree[p], reverse=True)
while len(dense_subgraph) < k and candidates:
    node = candidates.pop(0)
    if node not in dense_subgraph:
        dense_subgraph.add(node)
        candidates.extend(nb for nb in self.backend[node]
                          if nb not in dense_subgraph)
        candidates.sort(key=lambda p: sum(1 for nb in self.backend[p]
                                           if nb in dense_subgraph), reverse=True)
dense_list = sorted(dense_subgraph)

# IFWBAP within dense subgraph for bottleneck qubits
interaction_weight = defaultdict(float)
for g, qubits in self.access.items():
    if len(qubits) == 2:
        key = (min(qubits[0],qubits[1]), max(qubits[0],qubits[1]))
        interaction_weight[key] += 1

def local_bfs_cost(lq, phys_c, placed):
    return sum(interaction_weight.get((min(lq,pl),max(lq,pl)),0) *
               self.distance_matrix[phys_c][pp] for pl, pp in placed.items())

anchor_lq = max(bottleneck_qubits,
    key=lambda lq: sum(interaction_weight.get((min(lq,o),max(lq,o)),0)
                        for o in bottleneck_qubits if o != lq))
anchor_phys = min(dense_list,
    key=lambda p: sum(self.distance_matrix[p][o] for o in dense_list if o != p)
                  / max(len(dense_list)-1, 1))

lq_to_phys = {anchor_lq: anchor_phys}; placed_phys = {anchor_phys}
unplaced_bn = [lq for lq in bottleneck_qubits if lq != anchor_lq]
while unplaced_bn:
    next_lq = max(unplaced_bn, key=lambda lq: sum(
        interaction_weight.get((min(lq,pl),max(lq,pl)),0) for pl in lq_to_phys))
    cands = [p for p in dense_list if p not in placed_phys] or \
            [p for p in physical_qubits if p not in placed_phys]
    best_p = min(cands, key=lambda p: local_bfs_cost(next_lq, p, lq_to_phys))
    lq_to_phys[next_lq] = best_p; placed_phys.add(best_p); unplaced_bn.remove(next_lq)

# Expand remaining via standard BFS
all_logical = sorted(set(q for qs in self.access.values() for q in qs))
unplaced = [lq for lq in all_logical if lq not in lq_to_phys]
interaction_neighbors = defaultdict(dict)
for (q1,q2), w in interaction_weight.items():
    interaction_neighbors[q1][q2] = w; interaction_neighbors[q2][q1] = w
while unplaced:
    next_lq = max(unplaced, key=lambda lq: sum(
        interaction_neighbors[lq].get(pl,0) for pl in lq_to_phys))
    cands = [nb for p in placed_phys for nb in self.backend[p]
             if nb not in placed_phys] or \
            [p for p in physical_qubits if p not in placed_phys]
    best_p = min(cands, key=lambda p: sum(
        interaction_neighbors[next_lq].get(pl,0) * self.distance_matrix[p][pp]
        for pl, pp in lq_to_phys.items()))
    lq_to_phys[next_lq] = best_p; placed_phys.add(best_p); unplaced.remove(next_lq)
# → apply bijection enforcement
```

IDEA_NAME: Topological Momentum Heat Diffusion Placement (TMHDP)
DESCRIPTION: Inspired by heat diffusion in physical systems: process 2Q gates in topological order and maintain a "heat map" over physical qubits representing accumulated interaction pressure. When a new logical qubit is first encountered, it is placed on the coolest available hardware region (minimizing collision with existing heat sources). Placed qubit interactions then "heat" their physical locations and this heat diffuses to neighboring hardware qubits with exponential decay. This creates natural spatial separation of interacting qubit clusters.
ALGORITHMIC_APPROACH:
1. Initialize `heat[p] = 0.0` for all physical qubits; `lq_to_phys = {}`, `placed_phys = set()`
2. Process 2Q gates in topological order (sort by topological layer, then gate id)
3. For each gate `(l1, l2)`:
   a. If `l1` unplaced and `l2` unplaced: place `l1` on coolest unoccupied physical, `l2` on coolest unoccupied hardware neighbor of `l1`'s position
   b. If only `l1` placed: place `l2` on coolest unoccupied hardware neighbor of `l1`'s physical qubit (fallback: globally coolest)
   c. If only `l2` placed: symmetric
   d. If both placed: add interaction heat at both physical positions
4. After each gate: diffuse `heat[p] += α * mean(heat[nb] for nb in backend[p])` for all `p`
5. Fill remaining via globally-coolest unoccupied physical qubits
6. Apply bijection enforcement
COLLISION_PREVENTION: All placements check `placed_phys`; first-encountered logical qubit gets an exclusive physical assignment immediately. Heat diffusion never reassigns qubits — it only influences future placements.
WHY_NOVEL: A fully dynamic, physics-inspired placement model with no analog in quantum compilation literature. Heat diffusion naturally creates spatial "repulsion" between heavily-interacting qubit groups, distributing interaction load across the hardware. This is fundamentally different from static interaction graphs or greedy centrality-based approaches.
NOVELTY_SCORE: 9
PROBABILITY_SCORE: 6
EFFORT_SCORE: 7
FEASIBILITY_SCORE: 9
AVERAGE_SCORE: 7.8

**Reference code (core):**
```python
from collections import defaultdict, deque
import math

gates_2q = {g: qubits for g, qubits in self.access.items() if len(qubits) == 2}
schedule_2q = sorted(gates_2q.keys())
physical_qubits = sorted(self.backend.keys())

# Topological layer
predecessors = defaultdict(set); successors = defaultdict(set)
last_on = {}
for g in schedule_2q:
    for q in gates_2q[g]:
        if q in last_on:
            pred = last_on[q]; successors[pred].add(g); predecessors[g].add(pred)
        last_on[q] = g
layer = {}
bfs_q = deque([g for g in schedule_2q if not predecessors[g]])
for g in bfs_q: layer.setdefault(g, 0)
while bfs_q:
    g = bfs_q.popleft()
    for s in successors[g]:
        new_l = layer[g] + 1
        if layer.get(s, -1) < new_l: layer[s] = new_l; bfs_q.append(s)

alpha = 0.1  # diffusion coefficient
heat = {p: 0.0 for p in physical_qubits}
lq_to_phys = {}; placed_phys = set()

def diffuse():
    new_heat = {}
    for p in physical_qubits:
        nbs = [nb for nb in self.backend[p]]
        avg = sum(heat[nb] for nb in nbs) / len(nbs) if nbs else 0
        new_heat[p] = heat[p] + alpha * avg
    heat.update(new_heat)

sorted_gates = sorted(schedule_2q, key=lambda g: (layer.get(g, 0), g))
for g in sorted_gates:
    l1, l2 = gates_2q[g]
    l1_placed, l2_placed = l1 in lq_to_phys, l2 in lq_to_phys

    if not l1_placed and not l2_placed:
        avail = [p for p in physical_qubits if p not in placed_phys]
        p1 = min(avail, key=lambda p: heat[p])
        lq_to_phys[l1] = p1; placed_phys.add(p1)
        nb_avail = [nb for nb in self.backend[p1] if nb not in placed_phys]
        if not nb_avail: nb_avail = [p for p in avail if p != p1 and p not in placed_phys]
        if nb_avail:
            p2 = min(nb_avail, key=lambda p: heat[p])
            lq_to_phys[l2] = p2; placed_phys.add(p2)
    elif l1_placed and not l2_placed:
        p1 = lq_to_phys[l1]
        nb_avail = [nb for nb in self.backend[p1] if nb not in placed_phys] or \
                   [p for p in physical_qubits if p not in placed_phys]
        if nb_avail:
            p2 = min(nb_avail, key=lambda p: heat[p])
            lq_to_phys[l2] = p2; placed_phys.add(p2)
    elif l2_placed and not l1_placed:
        p2 = lq_to_phys[l2]
        nb_avail = [nb for nb in self.backend[p2] if nb not in placed_phys] or \
                   [p for p in physical_qubits if p not in placed_phys]
        if nb_avail:
            p1 = min(nb_avail, key=lambda p: heat[p])
            lq_to_phys[l1] = p1; placed_phys.add(p1)
    else:
        heat[lq_to_phys[l1]] += 1.0; heat[lq_to_phys[l2]] += 1.0
    diffuse()

# Fill remaining
all_logical = sorted(set(q for qs in self.access.values() for q in qs))
unplaced = [lq for lq in all_logical if lq not in lq_to_phys]
avail = sorted([p for p in physical_qubits if p not in placed_phys], key=lambda p: heat[p])
for lq, phys in zip(unplaced, avail): lq_to_phys[lq] = phys
# → apply bijection enforcement
```

IDEA_NAME: Front-Layer Dry-Run Multi-Candidate Simulation Selection (FLDRMCSS)
DESCRIPTION: Generate K diverse candidate initial mappings (by varying the anchor choice in IFWBAP or by random perturbation), then for each candidate, simulate the first M SWAP steps of the Qlosure routing heuristic on the actual circuit (a "dry run") and count the SWAPs accumulated. Select the candidate that accumulates the fewest SWAPs in the first M steps as the initial mapping. This meta-strategy uses the downstream routing heuristic as an oracle to evaluate placement quality, adapting to the specific circuit-hardware combination.
ALGORITHMIC_APPROACH:
1. Generate K candidate mappings: {trivial, IFWBAP with different anchors, random}
2. For each candidate mapping `σ_k`:
   a. Initialize `mapping_dict` and `reverse_mapping_dict` from `σ_k`
   b. Build DAG (can be pre-built once, reused across candidates)
   c. Initialize front layer
   d. Simulate M routing steps using `execute_algorithm` with `max_swaps=M` (modified to terminate early)
   e. Record `swap_count_k`
3. Select `σ_best = argmin_k(swap_count_k)`
4. Use `σ_best` as final mapping
COLLISION_PREVENTION: All K candidate mappings are generated with valid bijection enforcement. No mapping manipulation during simulation changes the selected mapping.
WHY_NOVEL: Rather than a static heuristic, FLDRMCSS uses the actual routing algorithm as a quality oracle. It is a "planning by simulation" approach — no existing quantum compiler uses the routing algorithm's output to score initial placements. The key insight is that the Qlosure heuristic itself encodes knowledge about what placements are good; we exploit this knowledge at placement time.
NOVELTY_SCORE: 8
PROBABILITY_SCORE: 8
EFFORT_SCORE: 5
FEASIBILITY_SCORE: 10
AVERAGE_SCORE: 7.8

**Reference code (core, showing integration pattern):**
```python
# In init_mapping, instead of running the full algorithm once,
# generate K candidates and select the best via dry-run scoring.
# This method requires access to generate_dag and execute_algorithm.

import copy

K = 5  # Number of candidate mappings to evaluate
```

IDEA_NAME: Hierarchical Spectral Bisection Dendrogram Alignment (HSBDA)
DESCRIPTION: Recursively bisect the weighted interaction graph using the Fiedler vector (spectral bisection) to build a dendrogram of logical qubit groups. Simultaneously, recursively bisect the hardware graph using the same spectral method to build a hardware dendrogram. Align the two dendrograms top-down: at each level, match the pair of interaction halves to the pair of hardware halves that minimizes the total inter-cut interaction weight crossing the hardware bisection. This hierarchically preserves multi-scale structure from circuit to hardware.
ALGORITHMIC_APPROACH:
1. `spectral_bisect(G, nodes)` → split `nodes` into two halves using Fiedler vector sign
2. Recursively bisect logical interaction graph: `logic_tree = recursive_bisect(G_int, all_logical)`
3. Recursively bisect hardware graph: `hw_tree = recursive_bisect(G_hw, all_physical)` (stop at singleton)
4. Align trees top-down: at each level, try both orderings of hardware children against interaction children; pick the ordering that minimizes cross-cut interaction weight on the hardware side
5. At leaf level, assign individual logical → individual physical by IFWBAP within the matched pair
6. Apply bijection enforcement
COLLISION_PREVENTION: Tree leaves are disjoint sets; leaf-level assignment is constrained to the matched hardware subtree. Bijection enforcement resolves any residual conflicts.
WHY_NOVEL: Hierarchical bisection of both graphs simultaneously — and aligning their dendrograms — is a completely novel paradigm for quantum placement. It operates at multiple scales simultaneously, ensuring global and local structure is preserved. Classical VLSI partitioning uses similar ideas, but this is novel in the quantum compilation context with hardware-topology-specific bisection.
NOVELTY_SCORE: 9
PROBABILITY_SCORE: 6
EFFORT_SCORE: 5
FEASIBILITY_SCORE: 9
AVERAGE_SCORE: 7.3

```python
import numpy as np
import networkx as nx
from collections import defaultdict

def spectral_bisect(G, nodes):
    """Split nodes into two halves using Fiedler vector sign."""
    sub = G.subgraph(nodes)
    if len(nodes) <= 1: return list(nodes), []
    if len(nodes) == 2: return [list(nodes)[0]], [list(nodes)[1]]
    L = nx.normalized_laplacian_matrix(sub).toarray()
    try:
        eigvals, eigvecs = np.linalg.eigh(L)
        fiedler = eigvecs[:, 1]
        node_list = list(nodes)
        half1 = [node_list[i] for i, v in enumerate(fiedler) if v <= 0]
        half2 = [node_list[i] for i, v in enumerate(fiedler) if v > 0]
        if not half1 or not half2:
            mid = len(node_list)//2
            half1, half2 = node_list[:mid], node_list[mid:]
    except Exception:
        node_list = sorted(nodes)
        mid = len(node_list)//2
        half1, half2 = node_list[:mid], node_list[mid:]
    return half1, half2

def build_tree(G, nodes, depth=0, max_depth=6):
    if len(nodes) <= 1 or depth >= max_depth:
        return {'nodes': list(nodes), 'children': None}
    h1, h2 = spectral_bisect(G, nodes)
    return {'nodes': list(nodes),
            'children': [build_tree(G, h1, depth+1, max_depth),
                         build_tree(G, h2, depth+1, max_depth)]}

# Build interaction graph
G_int = nx.Graph()
interaction_weight = defaultdict(float)
logical_qubit_set = set()
for gate, qubits in self.access.items():
    for q in qubits: logical_qubit_set.add(q)
    if len(qubits) == 2:
        q1, q2 = qubits
        interaction_weight[(min(q1,q2),max(q1,q2))] += 1
        if G_int.has_edge(q1,q2): G_int[q1][q2]['weight'] += 1
        else: G_int.add_edge(q1, q2, weight=1)

G_hw = nx.Graph([(p, nb) for p, nbs in self.backend.items() for nb in nbs])
physical_qubits = sorted(self.backend.keys())

logic_tree = build_tree(G_int, set(logical_qubit_set))
hw_tree = build_tree(G_hw, set(physical_qubits))

# Recursive alignment: match logic subtree to hw subtree
lq_to_phys = {}
def align(l_node, h_node):
    if l_node['children'] is None or h_node['children'] is None:
        l_qubits = l_node['nodes']
        h_qubits = h_node['nodes']
        # Within leaf pair: IFWBAP-style assignment
        for i, lq in enumerate(l_qubits[:len(h_qubits)]):
            lq_to_phys[lq] = h_qubits[i]
        return
    lc1, lc2 = l_node['children']
    hc1, hc2 = h_node['children']
    # Score two assignment options: (lc1→hc1, lc2→hc2) vs (lc1→hc2, lc2→hc1)
    def cross_cut_score(l_nodes, h_nodes):
        h_set = set(h_nodes)
        return sum(w for (q1,q2), w in interaction_weight.items()
                   if q1 in set(l_nodes) and q2 in set(l_nodes)
                   and any(self.distance_matrix[lq_to_phys.get(q1, h_nodes[0])]
                                               [lq_to_phys.get(q2, h_nodes[0])] > 1
                           for _ in [1]))
    # Simple heuristic: match by size similarity
    s1 = abs(len(lc1['nodes']) - len(hc1['nodes'])) + abs(len(lc2['nodes']) - len(hc2['nodes']))
    s2 = abs(len(lc1['nodes']) - len(hc2['nodes'])) + abs(len(lc2['nodes']) - len(hc1['nodes']))
    if s1 <= s2:
        align(lc1, hc1); align(lc2, hc2)
    else:
        align(lc1, hc2); align(lc2, hc1)

align(logic_tree, hw_tree)
```

IDEA_NAME: Stochastic Local Search QAP Minimization (SLSQAP)
DESCRIPTION: Placement as a Quadratic Assignment Problem (QAP): minimize `∑_{(l1,l2)} w[l1,l2] × dist[σ(l1)][σ(l2)]` over all permutations `σ`. This directly minimizes the weighted sum of hardware distances for all interacting qubit pairs — the exact metric that correlates with SWAP count. While QAP is NP-hard in general, stochastic local search (random restart + 2-opt local swap improvement) finds near-optimal solutions efficiently for n ≤ 150 qubits. Uses the precomputed `distance_matrix` directly as the cost oracle.
ALGORITHMIC_APPROACH:
1. Build interaction weight matrix `W[l1][l2]` from `self.access`
2. Start from IFWBAP mapping as initial solution `σ`
3. Compute initial cost `C(σ) = ∑_{l1<l2} W[l1][l2] × dist[σ(l1)][σ(l2)]`
4. Repeat for N_iter iterations:
   a. Pick two random logical qubits `l1, l2`; compute delta cost of swapping `σ(l1)` and `σ(l2)`
   b. Accept if `delta < 0` (steepest descent) or with small probability `ε` (stochastic escape from local minima)
5. Keep best solution across all iterations
6. Apply bijection enforcement (mapping already valid permutation throughout)
COLLISION_PREVENTION: Each candidate solution is a permutation of physical qubits — swapping two entries in the mapping never violates bijectivity. The bijection enforcement is a no-op since the QAP maintains a valid permutation throughout.
WHY_NOVEL: Explicitly formulates initial placement as QAP with the exact theoretical cost metric (weighted interaction-distance sum). No existing quantum compiler optimizes this exact objective at placement time — SABRE and IFWBAP use greedy heuristics that approximate this objective. The QAP formulation with `distance_matrix` as a precomputed oracle is elegant and directly minimizes the routing cost proxy.

IDEA_NAME: Force-Directed Embedding Procrustes-Aligned Placement (FDEPAP)
DESCRIPTION: Use a physics-inspired force-directed layout to embed both the logical interaction graph and the hardware graph into 2D Euclidean space using spring forces proportional to interaction weights / hardware edge lengths. After independent embedding, apply Procrustes analysis (rotation + scaling + reflection) to align the two 2D embeddings into the same coordinate system. Then, for each logical qubit, assign it to the nearest unoccupied hardware node in the aligned 2D space. This geometric approach exploits the spatial structure of hardware topologies (IBM's heavy-hex is nearly 2D planar).
ALGORITHMIC_APPROACH:
1. Embed hardware graph in 2D: `pos_hw = networkx.spring_layout(G_hw, seed=42)` → `pos_hw[p] = (x, y)`
2. Embed logical interaction graph in 2D: `pos_int = networkx.spring_layout(G_int, weight='weight', seed=42)`
3. Build matrices `A = np.array([pos_hw[p] for p in physical_qubits])` and `B = np.array([pos_int[lq] for lq in logical_qubits])`
4. Apply Procrustes: `scipy.spatial.procrustes(A, B)` → aligned `B_aligned`
5. For each logical qubit (sorted by interaction degree descending), assign to nearest unoccupied hardware position in Euclidean space
6. Apply bijection enforcement
COLLISION_PREVENTION: Greedy nearest-unoccupied assignment processes logical qubits one-by-one with explicit occupancy tracking. Bijection enforcement resolves the full `num_qubits` mapping.
WHY_NOVEL: A geometric alignment approach that exploits the near-planarity of real quantum hardware topologies (IBM heavy-hex, Google Sycamore). By embedding both graphs in 2D and aligning them geometrically, the algorithm implicitly captures global topological structure that graph-based methods (BFS, centrality) miss. Procrustes alignment for quantum placement is unpublished.

IDEA_NAME: Interaction Graph Degree-Profile Subgraph Isomorphism with Degree Pruning (IGDPSIDP)
DESCRIPTION: Attempt to find a hardware subgraph where the high-weight edges of the interaction graph can be embedded with all heavy interaction pairs on adjacent hardware edges. Rather than full subgraph isomorphism (exponential), prune the search aggressively: (1) only embed edges with weight ≥ mean interaction weight (the "heavy" interaction subgraph), (2) only consider physical qubits with hardware degree ≥ logical interaction degree, (3) use networkx's VF2pp algorithm with early termination after the first feasible embedding. Remaining qubits placed via IFWBAP expansion.
ALGORITHMIC_APPROACH:
1. Compute mean interaction weight `threshold = mean(w for w in interaction_weight.values())`
2. Build heavy interaction graph `G_heavy` = subgraph with edges ≥ threshold
3. For each logical qubit in `G_heavy`, compute its interaction degree `d_L[lq]`
4. Build filtered hardware graph `G_hw_filtered` = only physical qubits with `degree ≥ min(d_L)`
5. Try `vf2pp_isomorphisms(G_hw_filtered, G_heavy, ...)` with timeout (2 seconds)
6. If isomorphism found: use it for heavy qubits; fill rest via IFWBAP expansion
7. If timeout/no isomorphism: degrade threshold and retry once; otherwise fall back to IFWBAP
8. Apply bijection enforcement
COLLISION_PREVENTION: VF2 isomorphism returns a valid injective mapping. IFWBAP expansion uses `placed_phys` exclusion. Bijection enforcement ensures full permutation.
WHY_NOVEL: Targeting exact adjacency for the circuit's *heaviest* interactions is the most direct path to SWAP elimination. VF2pp with degree pruning makes this computationally viable for the heavy-interaction subgraph (which is typically small). The combination of degree-pruned VF2pp isomorphism for the heavy subgraph with IFWBAP fallback for the rest is a novel hybrid strategy.

IDEA_NAME: Interaction-Weighted Resistance Distance Rank Matching (IWRDRM)
DESCRIPTION: Effective resistance (resistance distance) in an electrical network is a richer graph distance metric than BFS hop-count: it accounts for all paths simultaneously, not just the shortest path. For a hardware graph viewed as a resistor network (each edge = 1Ω resistor), the effective resistance `R_eff(p1, p2)` between two physical qubits reflects the true "routing effort" between them, capturing bottlenecks and parallelism in the hardware. IWRDRM assigns logical qubits with high interaction weight to physical qubit pairs with low effective resistance, using the pseudoinverse of the graph Laplacian.
ALGORITHMIC_APPROACH:
1. Build hardware Laplacian matrix `L_hw`; compute its pseudoinverse `L_hw_pinv = np.linalg.pinv(L_hw)`
2. Compute effective resistance: `R[p1][p2] = L_hw_pinv[p1,p1] + L_hw_pinv[p2,p2] - 2*L_hw_pinv[p1,p2]`
3. For each logical qubit `lq`, compute `total_resistance_demand[lq] = ∑_{lq'} interaction_weight[(lq,lq')] × (ideal: min R for those qubits)`
4. Build cost matrix `C[l][p] = ∑_{l'} interaction_weight[l,l'] × R_mean[p]` where `R_mean[p] = mean(R[p][p'] for p' ≠ p)`
5. Apply Hungarian on `C` for globally optimal assignment
6. Apply bijection enforcement
COLLISION_PREVENTION: Hungarian algorithm produces a bijection. Padding to `num_qubits × num_qubits` ensures validity.
WHY_NOVEL: Effective resistance is a fundamentally richer metric than BFS distance for capturing routing difficulty — it accounts for all parallel paths and bottlenecks in the hardware graph. No existing quantum compiler uses effective resistance for qubit placement. For superconducting hardware with irregular topologies (IBM heavy-hex), effective resistance captures connectivity nuances that BFS distance misses entirely.
NOVELTY_SCORE: 9
PROBABILITY_SCORE: 7
EFFORT_SCORE: 6
FEASIBILITY_SCORE: 10
AVERAGE_SCORE: 8.0

**Reference code (core):**

```python
max_int = max(interaction_degree.values(), default=1)
max_R = R_mean.max() + 1e-9

n_l = len(logical_qubits)
C = np.zeros((n_l, n_p))
for i, lq in enumerate(logical_qubits):
    norm_int = interaction_degree[lq] / max_int
    for j in range(n_p):
        norm_R = R_mean[j] / max_R
        # High-interaction logical should go to low-resistance physical
        C[i, j] = norm_int * norm_R + (1 - norm_int) * (1 - norm_R)

row_ind, col_ind = linear_sum_assignment(C)
lq_to_phys = {logical_qubits[i]: physical_qubits[j]
              for i, j in zip(row_ind, col_ind)}
# → apply bijection enforcement
```
