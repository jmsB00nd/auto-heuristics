IDEA_NAME: Interaction Graph Density Lookahead Cost (IGDLC)
DESCRIPTION: Precompute for every logical qubit pair (q1,q2) the total number of 2-qubit gates between them in the **entire remaining circuit** (not just F∪E). Use this global interaction frequency as a gate weight — pairs that interact frequently throughout the circuit should be physically close at all times, not just when they next appear in the extended layer window. This is a full-circuit density signal, unlike the local-window lookahead of SABRE.
MATHEMATICAL_FORMULATION:
```
freq(q1,q2) = total remaining gates between q1 and q2 in the DAG

IGDLC(SWAP_s) = max_decay_s · [
    (1/|F|) · Σ_{g∈F} freq(q1_g, q2_g) · d(Q1_g, Q2_g)
  + W · (1/|E|) · Σ_{g∈E} freq(q1_g, q2_g) · d(Q1_g, Q2_g) / layer_index(g)
]
```
Precomputed offline; freq updates incrementally as gates execute.
WHY_NOVEL: SABRE and its variants weight gates by local dependency count or layer position. IGDLC weights by **global future interaction density** — a pair with freq=20 needs to be co-located urgently regardless of whether their next shared gate is in F or 100 steps ahead. This is fundamentally different from any sliding-window lookahead.
NOVELTY_SCORE: 8
PROBABILITY_SCORE: 8
EFFORT_SCORE: 7
AVERAGE_SCORE: 7.7
STATUS: KEPT
ELIMINATION_REASON: N/A

IDEA_NAME: Minimum Spanning Tree Alignment Cost (MSTAC)
DESCRIPTION: Build the weighted **interaction graph** G_I from the remaining circuit: nodes = logical qubits, edge weight(q1,q2) = total remaining interactions between q1 and q2. Compute the MST of G_I. The MST captures the global interaction skeleton — the minimum-cost subgraph that spans all interacting qubits. The cost function measures how well the current physical mapping stretches this MST onto the coupling graph. A mapping that embeds the MST with low total physical distance is globally efficient.
MATHEMATICAL_FORMULATION:
```
MST(G_I) = minimum spanning tree of interaction graph (edge weights = interaction counts)

MSTAC(SWAP_s) = max_decay_s · Σ_{(q1,q2) ∈ MST(G_I)} w_MST(q1,q2) · d(φ(q1), φ(q2))

where w_MST(q1,q2) = interaction count on MST edge (q1,q2)
      φ = current qubit mapping (updated after simulating SWAP_s)
```
MST is recomputed periodically (or updated incrementally using Borůvka). Convergence: d(φ(q1),φ(q2))→1 as qubits route adjacent.
WHY_NOVEL: No existing routing cost function uses the MST of the interaction graph as its alignment target. The MST is the **globally optimal interaction skeleton** — minimizing its physical stretch minimizes redundant SWAP overhead across the full circuit. The MST naturally eliminates redundant edges that cause wasted routing effort.
NOVELTY_SCORE: 9
PROBABILITY_SCORE: 7
EFFORT_SCORE: 6
AVERAGE_SCORE: 7.3
STATUS: KEPT

IDEA_NAME: Marginal Distance Reduction Cost (MDRC)
DESCRIPTION: Instead of measuring the **cost of the current state**, directly measure the **benefit of each SWAP action** — how much total weighted distance it actually reduces across F∪E. The SWAP with maximum distance reduction (most negative MDRC) is selected. This inverts the standard framework: we optimize over actions, not states. The cost is the algebraic change in total weighted distance, not the total distance itself.
MATHEMATICAL_FORMULATION:
```
w_g = (deps_g + 1) / layer_factor(g)

MDRC(SWAP_s) = Σ_{g∈F∪E} w_g · [d_after_SWAP_s(Q1_g, Q2_g) - d_before(Q1_g, Q2_g)]

Select SWAP_s* = argmin_{s} MDRC(SWAP_s)
```
Negative MDRC = net distance reduction = good SWAP. Convergence: the algorithm always makes local progress (or stalls → decay breaks ties). Terminates when F empties.
WHY_NOVEL: Standard cost functions (SABRE, LOOKAHEAD) measure the state's absolute cost and pick the SWAP that minimizes it. MDRC measures the **delta** — the actual marginal improvement — making it a direct action-value function rather than a state-value function. This is philosophically closer to Q-learning but without the complexity of RL.
NOVELTY_SCORE: 7
PROBABILITY_SCORE: 7
EFFORT_SCORE: 8
AVERAGE_SCORE: 7.3
STATUS: KEPT
ELIMINATION_REASON: N/A

IDEA_NAME: Adaptive Window Lookahead Cost (AWLC)
DESCRIPTION: Dynamically adjust the extended layer weight W based on real-time routing progress. If many front-layer gates are being resolved quickly (high progress rate), the extended layer weight shrinks — we trust the front layer to guide efficiently. If routing is stalling (few front-layer gates resolving), the extended layer weight grows to provide stronger global lookahead. This is a feedback-controlled lookahead mechanism.
MATHEMATICAL_FORMULATION:
```
progress_rate(t) = (gates resolved in last K steps) / K

W_adaptive(t) = W_max · exp(-λ · progress_rate(t))   [W_max, λ are hyperparameters]

AWLC(SWAP_s) = max_decay_s · [
    (1/|F|) · Σ_{g∈F} (deps_g+1) · d(Q1_g, Q2_g)
  + W_adaptive(t) · (1/|E|) · Σ_{g∈E} (deps_g+1) · d(Q1_g, Q2_g) / layer_index(g)
]
```
Convergence: same as baseline — W_adaptive ≥ 0 and distances drive toward executable gates.
WHY_NOVEL: All existing methods use a fixed W (SABRE: W=0.5, LOOKAHEAD: constant). AWLC uses **online feedback** from routing efficiency to self-tune the lookahead depth. When routing is efficient, less lookahead is needed; when stuck, more global guidance is injected. This is the first adaptive lookahead mechanism based on routing momentum.
NOVELTY_SCORE: 7
PROBABILITY_SCORE: 7

IDEA_NAME: Causal Unlock Width Cost (CUWC)
DESCRIPTION: For each gate g, compute its **unlock width**: the number of gate successors in the DAG that have g as their LAST unresolved predecessor. These are gates that will IMMEDIATELY become executable once g is executed. Gates with high unlock width are "activation keys" — resolving them triggers a cascade of newly executable gates. They deserve higher routing urgency.
MATHEMATICAL_FORMULATION:
```
unlock_width(g) = |{g' ∈ DAG : g is the unique unresolved predecessor of g' among all predecessors(g')}|

CUWC(SWAP_s) = max_decay_s · [
    (1/|F|) · Σ_{g∈F} (1 + unlock_width(g)) · d(Q1_g, Q2_g)
  + W · (1/|E|) · Σ_{g∈E} (1 + unlock_width(g)) · d(Q1_g, Q2_g) / layer_index(g)
]
```
unlock_width updates dynamically as front-layer gates execute. Convergence: weight ≥ 1, distance drives toward adjacency.
WHY_NOVEL: Critical path methods (CPGUC, excluded) weight by longest remaining path **length**. CUWC weights by DAG fan-out **width** at the current execution frontier — a completely different dimension of circuit structure. It captures parallel activation potential, not sequential depth.
NOVELTY_SCORE: 7
PROBABILITY_SCORE: 7
EFFORT_SCORE: 7
AVERAGE_SCORE: 7.0

IDEA_NAME: DAG Topological Schedule Pressure Cost (DTSPC)
DESCRIPTION: Assign each gate a **topological level** T(g) = minimum DAG depth from source to g (precomputed). Define a routing "step budget" as T(g) - current_routing_step. Gates with small budgets (low T(g) relative to current step, meaning they are "overdue") have high scheduling pressure. Weight routing cost inversely by remaining budget.
MATHEMATICAL_FORMULATION:
```
T(g) = topological_level(g)   [precomputed: min DAG depth]
budget(g) = max(1, T(g) - current_step)
urgency(g) = 1 / budget(g)

DTSPC(SWAP_s) = max_decay_s · [
    (1/|F|) · Σ_{g∈F} urgency(g) · d(Q1_g, Q2_g)
  + W · (1/|E|) · Σ_{g∈E} urgency(g) · d(Q1_g, Q2_g) / layer_index(g)
]
```
Urgency is dynamic — increases each routing step. Convergence: urgency > 0, distances monotonically bounded, algorithm terminates as F empties.
WHY_NOVEL: The baseline weights by dag_dependencies_count (static fan-in). DTSPC uses a **dynamic countdown** from topological level, creating urgency that grows in real time as the routing step progresses. This models gates as having real scheduling deadlines that tighten with each SWAP.
NOVELTY_SCORE: 7
PROBABILITY_SCORE: 7
EFFORT_SCORE: 7

IDEA_NAME: Qubit Centrality Displacement Cost (QCDC)
DESCRIPTION: Precompute betweenness centrality bc(v) for all physical qubits in the coupling graph. For each gate (Q1,Q2) at distance d, routing must pass through vertices along the shortest path. The most central vertex on this path is the "routing bottleneck" — it is a shared resource many other paths also require. Weight gate distance by the maximum centrality along its routing path.
MATHEMATICAL_FORMULATION:
```
bc(v) = betweenness centrality of vertex v in coupling graph G (precomputed, normalized to [0,1])
path_bottleneck(Q1,Q2) = max_{v ∈ any_SP(Q1,Q2)} bc(v)

QCDC(SWAP_s) = max_decay_s · [
    (1/|F|) · Σ_{g∈F} (deps_g+1) · d(Q1_g,Q2_g) · (1 + α · path_bottleneck(Q1_g,Q2_g))
  + W · (1/|E|) · Σ_{g∈E} (deps_g+1) · d(Q1_g,Q2_g) · (1 + α · path_bottleneck(Q1_g,Q2_g)) / layer_index(g)
]
```
α ∈ [0,1] controls bottleneck sensitivity. path_bottleneck precomputed per qubit pair.
WHY_NOVEL: No existing cost function multiplies distance by the topological centrality of vertices on the routing path. Gates that must route through high-betweenness "hub" qubits (critical infrastructure of the coupling graph) are penalized — the router learns to resolve these gates first to free up shared routing resources.
NOVELTY_SCORE: 7
PROBABILITY_SCORE: 7
EFFORT_SCORE: 7
AVERAGE_SCORE: 7.0

IDEA_NAME: Neighborhood Overlap Complement Cost (NOCC)
DESCRIPTION: Define the **Jaccard topological distance** between two physical qubits using their closed neighborhoods: J_dist(Q1,Q2) = 1 - |N[Q1]∩N[Q2]| / |N[Q1]∪N[Q2]|. Two qubits with high neighborhood overlap share many common neighbors — they have more alternative routing paths and greater routing flexibility. Multiply hop-count distance by this Jaccard distance to amplify cost for pairs with disjoint neighborhoods (topological isolation).
MATHEMATICAL_FORMULATION:
```
N[Q] = {Q} ∪ neighbors(Q)   [closed neighborhood]
J(Q1,Q2) = |N[Q1] ∩ N[Q2]| / |N[Q1] ∪ N[Q2]|   [Jaccard similarity, precomputed]
J_dist(Q1,Q2) = 1 - J(Q1,Q2)

NOCC(SWAP_s) = max_decay_s · [
    (1/|F|) · Σ_{g∈F} (deps_g+1) · d(Q1_g,Q2_g) · (1 + β · J_dist(Q1_g,Q2_g))
  + W · (1/|E|) · Σ_{g∈E} (deps_g+1) · d(Q1_g,Q2_g) · (1 + β · J_dist(Q1_g,Q2_g)) / layer_index(g)
]
```
β ∈ [0,1]. All values precomputed. Convergence: multiplier ≥ 1, distance drives to adjacency.
WHY_NOVEL: Neighborhood Jaccard similarity is a standard graph-theoretic measure of local structural similarity but has never been used as a routing cost modifier. It captures a different dimension than hop count: two qubits at distance 2 in a densely-connected clique have J≈1 (easy to route), while two qubits at distance 2 in a chain have J≈0 (much harder).
NOVELTY_SCORE: 8
PROBABILITY_SCORE: 6
EFFORT_SCORE: 7
AVERAGE_SCORE: 7.0
STATUS: KEPT

IDEA_NAME: Gate Parallelism Potential Cost (GPPC)
DESCRIPTION: For each gate g ∈ F∪E, count how many OTHER gates in F∪E share NO logical qubit with g — these can execute concurrently. Call this concurrency(g). A gate with high concurrency has many parallel alternatives: the circuit can make progress on other gates while routing g. A gate with low concurrency (serial bottleneck) must be resolved before progress can resume. Weight routing cost INVERSELY by concurrency — serial bottleneck gates get highest priority.
MATHEMATICAL_FORMULATION:
```
concurrency(g) = |{g' ∈ F∪E : {q1_g, q2_g} ∩ {q1_{g'}, q2_{g'}} = ∅}|
serial_pressure(g) = 1 / (1 + concurrency(g))

GPPC(SWAP_s) = max_decay_s · [
    (1/|F|) · Σ_{g∈F} serial_pressure(g) · d(Q1_g, Q2_g)
  + W · (1/|E|) · Σ_{g∈E} serial_pressure(g) · d(Q1_g, Q2_g) / layer_index(g)
]
```
serial_pressure ∈ (0,1], recomputed each routing step. Convergence: weight bounded above by 1.
WHY_NOVEL: No existing cost function considers the **parallelism context** of each gate. Gates that are serial bottlenecks (no concurrent alternatives in F∪E) are penalized more — the router cannot make progress elsewhere while routing them. This is an information-theoretic view: serial_pressure is inversely related to the "routing degrees of freedom" available.
NOVELTY_SCORE: 8
PROBABILITY_SCORE: 7
EFFORT_SCORE: 6
AVERAGE_SCORE: 7.0
STATUS: KEPT
ELIMINATION_REASON: N/A

IDEA_NAME: Shortest Path Count-Weighted Distance Cost (SPCWDC)
DESCRIPTION: For each gate (Q1,Q2), count the total number of distinct shortest paths between Q1 and Q2 in the coupling graph. More shortest paths = more routing flexibility = lower effective routing difficulty. Divide distance by log(1 + path_count) to reduce cost for pairs with many routing alternatives, without extreme amplification for pairs with exponentially many paths.
MATHEMATICAL_FORMULATION:
```
paths(Q1,Q2) = number of distinct shortest paths from Q1 to Q2 (precomputed via BFS)

SPCWDC(SWAP_s) = max_decay_s · [
    (1/|F|) · Σ_{g∈F} (deps_g+1) · d(Q1_g,Q2_g) / log(1 + paths(Q1_g,Q2_g))
  + W · (1/|E|) · Σ_{g∈E} (deps_g+1) · d(Q1_g,Q2_g) / log(1 + paths(Q1_g,Q2_g)) / layer_index(g)
]
```
paths precomputed offline. Convergence: log(1+paths)≥log(2)>0 so denominator is bounded away from 0.
WHY_NOVEL: Existing methods treat all gates at distance d as equally difficult to route. SPCWDC distinguishes: two pairs at distance 3 in a Sycamore grid may have paths=8 vs paths=1 depending on topology. The pair with one path is far harder to route. This is a genuine topology-sensitivity improvement that costs only an offline BFS.
NOVELTY_SCORE: 7
PROBABILITY_SCORE: 6
EFFORT_SCORE: 7
AVERAGE_SCORE: 6.7
STATUS: KEPT

IDEA_NAME: Routing Subgraph Size Cost (RSSC)
DESCRIPTION: For each gate (Q1,Q2), define the **routing subgraph** RS(Q1,Q2) as the set of all vertices that lie on at least one shortest path from Q1 to Q2. The size |RS(Q1,Q2)| measures the volume of the routing "corridor" — large corridors offer more parallel routing flexibility. Penalize gates with small routing subgraphs (constrained corridors) more heavily.
MATHEMATICAL_FORMULATION:
```
RS(Q1,Q2) = {v ∈ V(G) : d(Q1,v) + d(v,Q2) = d(Q1,Q2)}   [vertices on some shortest path]
rs_size(Q1,Q2) = |RS(Q1,Q2)|

RSSC(SWAP_s) = max_decay_s · [
    (1/|F|) · Σ_{g∈F} (deps_g+1) · d(Q1_g,Q2_g) / rs_size(Q1_g,Q2_g)
  + W · (1/|E|) · Σ_{g∈E} (deps_g+1) · d(Q1_g,Q2_g) / rs_size(Q1_g,Q2_g) / layer_index(g)
]
```
rs_size ≥ 2 always (includes Q1 and Q2). Precomputed via BFS for all pairs. Convergence guaranteed.
WHY_NOVEL: Distinct from path COUNT (SPCWDC) — two pairs can have the same number of shortest paths but very different routing subgraph sizes. RSSC captures the **volumetric** routing flexibility, not just path multiplicity. It is also distinct from vertex connectivity, which measures minimum cuts rather than corridor volume.
NOVELTY_SCORE: 7
PROBABILITY_SCORE: 6
EFFORT_SCORE: 7
AVERAGE_SCORE: 6.7

IDEA_NAME: Layer Distance Variance Regularization Cost (LDVRC)
DESCRIPTION: Beyond minimizing total distance, regularize the **variance** of distances across the front layer. A high-variance distance distribution in F means some gates are nearly executable while others are far away — the router is making uneven progress. Penalizing variance encourages balanced, parallel routing effort. The SWAP that minimizes total cost + γ·variance is selected.
MATHEMATICAL_FORMULATION:
```
D_F(SWAP_s) = {d_after_SWAP_s(Q1_g, Q2_g) : g ∈ F}   [distance multiset after applying SWAP_s]
μ_F = mean(D_F),   σ²_F = variance(D_F)

f_dist(SWAP_s) = (1/|F|) · Σ_{g∈F} (deps_g+1) · d(Q1_g,Q2_g)
e_dist(SWAP_s) = (1/|E|) · Σ_{g∈E} (deps_g+1) · d(Q1_g,Q2_g) / layer_index(g)

LDVRC(SWAP_s) = max_decay_s · [f_dist + W · e_dist + γ · σ²_F]
```
σ²_F is bounded (max distance = graph diameter), γ controls regularization strength. Convergence: σ²_F term is bounded and additive — doesn't prevent distance reduction.
WHY_NOVEL: No routing cost function currently penalizes **distance distribution imbalance**. A configuration where one gate is at distance 1 and another at distance 6 is worse than both at distance 3 (same mean), because the far gate creates a serial bottleneck. LDVRC is the first variance-aware routing cost function.
NOVELTY_SCORE: 8
PROBABILITY_SCORE: 5
EFFORT_SCORE: 7
AVERAGE_SCORE: 6.7
STATUS: KEPT
ELIMINATION_REASON: N/A

IDEA_NAME: Degree Harmonic Centrality Path Cost (DHCPC)
DESCRIPTION: Replace hop-count distance with a **harmonic degree-weighted path cost**: for each vertex v on the shortest path from Q1 to Q2, contribute 1/deg(v) to the path cost. Low-degree vertices are scarce routing resources (bottlenecks) — routing through them costs more. High-degree hub qubits are "cheap" routing intermediaries.
MATHEMATICAL_FORMULATION:
```
SP(Q1,Q2) = any shortest path from Q1 to Q2 (sequence of vertices)
hdc_path(Q1,Q2) = Σ_{v ∈ SP(Q1,Q2)} 1/deg(v)   [harmonic degree sum along path]

DHCPC(SWAP_s) = max_decay_s · [
    (1/|F|) · Σ_{g∈F} (deps_g+1) · hdc_path(Q1_g, Q2_g)
  + W · (1/|E|) · Σ_{g∈E} (deps_g+1) · hdc_path(Q1_g, Q2_g) / layer_index(g)
]
```
hdc_path(Q,Q) = 0 when d=0. For adjacent pairs: hdc_path = 1/deg(Q1) + 1/deg(Q2). Precomputed per pair. Convergence: same as baseline.
WHY_NOVEL: Unlike effective resistance (excluded: ERCRC) which uses the full graph Laplacian pseudoinverse, DHCPC uses only local degree information along the path — a O(diameter) computation vs. O(n³). It captures vertex-level bottleneck cost with a simple, interpretable formula that rewards routing through high-degree hub qubits.
NOVELTY_SCORE: 7
PROBABILITY_SCORE: 6
EFFORT_SCORE: 7
AVERAGE_SCORE: 6.7

IDEA_NAME: Momentum-Penalized Direction Reversal Cost (MPDRC)
DESCRIPTION: Track the movement direction of each logical qubit across recent SWAPs using a spectral embedding of the coupling graph (first 2 Laplacian eigenvectors give 2D positions). For each qubit, maintain a momentum vector = average recent displacement direction. Penalize SWAPs that move a qubit in the opposite direction of its momentum (direction reversals are inefficient).
MATHEMATICAL_FORMULATION:
```
x(Q) = 2D spectral embedding position of physical qubit Q
momentum(q) = exponentially-weighted average of recent physical displacement vectors for qubit q
            = (1-α)·momentum(q) + α·(x(Q_new) - x(Q_old))   [updated after each SWAP]

For SWAP_s on edge (Qa, Qb), swapping logical qubits qa, qb:
  displacement_a = x(Qb) - x(Qa)   [new position of qa relative to old]
  reversal_a = max(0, -cos_angle(momentum(qa), displacement_a))   [0 if aligned, >0 if reversed]
  reversal_b = max(0, -cos_angle(momentum(qb), displacement_b))

MPDRC(SWAP_s) = baseline_cost(SWAP_s) · (1 + λ · (reversal_a + reversal_b))
```
λ > 0 controls reversal penalty. Convergence: multiplier ≥ 1 so baseline convergence is preserved.
WHY_NOVEL: No existing routing cost function uses **temporal momentum of qubit movement**. Routing oscillation (A→B→A→B) is a well-known failure mode; MPDRC directly penalizes it by tracking movement direction history. The spectral embedding provides a consistent 2D coordinate frame for any coupling topology.
NOVELTY_SCORE: 7
PROBABILITY_SCORE: 6
EFFORT_SCORE: 7
AVERAGE_SCORE: 6.7
STATUS: KEPT
ELIMINATION_REASON: N/A

IDEA_NAME: Circuit Depth Horizon Cost (CDHC)
DESCRIPTION: For each gate g, compute its **depth horizon** H(g) = max_DAG_depth - topological_level(g): the number of DAG levels remaining in the circuit after g. Gates near the end of the circuit (small H) have the least remaining "slack" — delaying them extends the total circuit depth directly. Weight distance inversely by depth horizon.
MATHEMATICAL_FORMULATION:
```
max_depth = maximum topological level in the DAG (precomputed)
H(g) = max_depth - topological_level(g)   [remaining circuit depth after g]
horizon_urgency(g) = 1 / (H(g) + 1)

CDHC(SWAP_s) = max_decay_s · [
    (1/|F|) · Σ_{g∈F} horizon_urgency(g) · d(Q1_g, Q2_g)
  + W · (1/|E|) · Σ_{g∈E} horizon_urgency(g) · d(Q1_g, Q2_g) / layer_index(g)
]
```
All values precomputed. horizon_urgency ∈ (0,1]. Convergence: same as baseline.
WHY_NOVEL: Distinct from critical path (excluded CPGUC, which measures path LENGTH from g to output). CDHC uses depth horizon — the number of circuit levels **remaining after** g — as a slack measure. Gates at the same topological level can have different depth horizons if the DAG has irregular depth structure.

PROBABILITY_SCORE: 6

IDEA_NAME: Qubit Sliding-Window Stability Penalty Cost (QSSPC)
DESCRIPTION: Instead of the baseline's per-SWAP exponential decay (which permanently discounts recently-used qubits), use a **sliding window count**: for each physical qubit Q, count how many SWAPs it participated in within the last K steps. High recent involvement = instability. Weight the baseline cost by an instability multiplier that resets after K steps.
MATHEMATICAL_FORMULATION:
```
K = sliding window size (hyperparameter, e.g. K=5)
recent_swaps_K(Q) = number of SWAPs involving Q in the last K routing steps

instability(Q) = recent_swaps_K(Q) / K   [∈ [0,1]]

QSSPC(SWAP_s) = (1 + β · (instability(Qa) + instability(Qb))) · [
    max_decay_s · (f_distance / |F| + W · (e_distance / |E|))
]
```
where f_distance and e_distance are computed as in the baseline. β ∈ [0,1].
Convergence: multiplier ≥ 1, baseline_cost drives to valid mapping. Window resets prevent permanent discounting.
WHY_NOVEL: The baseline decay parameter grows monotonically (qubits accumulate decay forever). QSSPC uses a fixed sliding window — a qubit's instability score resets to 0 after K steps of non-involvement. This prevents the decay parameter from growing unboundedly and causing late-circuit routing degradation. The window-based approach captures local temporal patterns more faithfully.
NOVELTY_SCORE: 6
PROBABILITY_SCORE: 6
EFFORT_SCORE: 8
AVERAGE_SCORE: 6.7
STATUS: KEPT
ELIMINATION_REASON: N/A

IDEA_NAME: Qubit Future Demand Cost (QFDC)
DESCRIPTION: For each physical qubit Q, count the total number of gates in F∪E that involve Q. High-demand qubits are routing bottlenecks. Weight gate distances by the sum of demand scores of both physical qubits.
MATHEMATICAL_FORMULATION:
```
demand(Q) = |{g ∈ F∪E : Q ∈ {Q1_g, Q2_g}}|
QFDC(SWAP_s) = max_decay_s · (1/|F|) · Σ_{g∈F} (demand(Q1_g)+demand(Q2_g))/2 · d(Q1_g,Q2_g) + ...
```
WHY_NOVEL: Qubit-level demand pressure rather than gate-level weighting.
NOVELTY_SCORE: 6
PROBABILITY_SCORE: 5
EFFORT_SCORE: 8
AVERAGE_SCORE: 6.3
STATUS: ELIMINATED
ELIMINATION_REASON: Subsumed by IGDLC. The global interaction frequency (IGDLC) is a strictly stronger signal than per-qubit demand count — it captures the specific pairing information (q1,q2), not just qubit-level demand. QFDC loses the directional interaction structure and is a weaker approximation of the same concept.

IDEA_NAME: Gate Urgency via Dependency Fan-In Count (GUDFC)
DESCRIPTION: Weight each gate by its fan-in: the number of gate predecessors in the DAG. Gates with many predecessors are "late" in the circuit and can't be delayed further.
MATHEMATICAL_FORMULATION:
```
fan_in(g) = |predecessors(g) in DAG|
GUDFC = Σ (1 + fan_in(g)/max_fan_in) · d(Q1,Q2) · (layer weights...)
```
WHY_NOVEL: Fan-in as urgency proxy distinct from fan-out or critical path length.
NOVELTY_SCORE: 5
PROBABILITY_SCORE: 5
EFFORT_SCORE: 8
AVERAGE_SCORE: 6.0
STATUS: ELIMINATED
ELIMINATION_REASON: Insufficiently novel. Fan-in count is closely related to topological level (monotone transformation for DAGs), and both DTSPC (topological level as deadline) and CDHC (depth horizon) already exploit DAG level structure more precisely and with stronger theoretical motivation.

---

IDEA_NAME: Resistance-Ratio Urgency Cost (RRUC)
DESCRIPTION: Measure routing difficulty as distance divided by vertex connectivity κ(Q1,Q2). Pairs separated by graph bottlenecks (low κ) get disproportionately high cost.
MATHEMATICAL_FORMULATION:
```
κ(Q1,Q2) = max vertex-disjoint paths from Q1 to Q2 (Menger's theorem)
RRUC(SWAP_s) = Σ (deps_g+1) · d(Q1,Q2)/(κ(Q1,Q2)+1) · (layer weights...)
```
WHY_NOVEL: Vertex connectivity as routing difficulty measure.
NOVELTY_SCORE: 7
PROBABILITY_SCORE: 5
EFFORT_SCORE: 6
AVERAGE_SCORE: 6.0
STATUS: ELIMINATED
ELIMINATION_REASON: Conceptually too similar to the excluded Maximum Flow Routing Pressure Cost (MFRPC). Both use min-cut / max-flow duality to measure routing bottleneck severity. Vertex connectivity ≤ edge connectivity ≤ minimum degree — it's a variation of the same theoretical concept with higher computational cost (requires n² max-flow computations).

---

IDEA_NAME: Circuit Momentum Transfer Cost (CMTC)
DESCRIPTION: Assign each logical qubit a physical momentum vector from recent displacement history in spectral embedding space. Penalize SWAPs that create "anti-momentum" (moving qubits against their velocity direction), modeling routing as a physical momentum-conservation problem.
MATHEMATICAL_FORMULATION:
```
p(q) = Σ_t α^t · (x(Q_t) - x(Q_{t-1}))   [exponentially-weighted momentum vector]
CMTC(SWAP_s) = baseline + λ · Σ_{q moved} |p(q) - proj_{displacement_s}(p(q))|²
```
WHY_NOVEL: Physics-inspired vector momentum conservation in routing.
NOVELTY_SCORE: 8
PROBABILITY_SCORE: 5
EFFORT_SCORE: 4
AVERAGE_SCORE: 5.7
STATUS: ELIMINATED
ELIMINATION_REASON: Redundant with MPDRC (Momentum-Penalized Direction Reversal Cost), which captures the same reversal-penalty concept more simply using cosine similarity. CMTC adds implementation complexity (vector norm projection, exponential weight accumulation) without a clear advantage over MPDRC's cleaner formulation. The marginal novelty over MPDRC does not justify the implementation effort.

## Top 3 Recommended for Implementation

**1. IGDLC** — Lowest implementation risk, highest expected payoff. Requires only one BFS pass per logical qubit pair at circuit load time. Drop-in replacement for `(deps+1)` weight with `freq(q1,q2)`.

**2. MDRC** — Elegant reformulation: evaluate the actual delta per SWAP rather than total state cost. Requires evaluating the baseline formula twice (before/after simulated SWAP), no precomputation.

**3. MSTAC** — Highest novelty. The MST of the interaction graph is a genuinely new global alignment target. Requires a Kruskal/Prim MST pass and maps cleanly onto the existing distance sum structure.
