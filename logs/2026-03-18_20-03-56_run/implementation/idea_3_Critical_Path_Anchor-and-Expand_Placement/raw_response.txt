**Algorithm: Critical Path Anchor-and-Expand Placement**

| Step | What it does |
|------|-------------|
| **1** | Collect all logical qubits and filter 2-qubit gates from `self.access` |
| **2** | Build a simplified per-qubit chained DAG over 2-qubit gates (consecutive gates sharing a qubit get a dependency edge) |
| **3** | Topological DP to find the longest chain — the critical path |
| **4** | Backtrack through `dp_prev` to reconstruct the path; extract unique qubits in path order |
| **5** | Precompute hardware centrality: mean BFS distance for every physical qubit |
| **6** | Find the most central adjacent hardware pair (min sum of centralities across all edges) as the anchor placement |
| **7** | Place the first two critical-path qubits onto that anchor pair |
| **8** | Build interaction-weight lookup (`interaction_neighbors`) from all 2-qubit gates |
| **9** | Greedily expand: each remaining critical-path qubit is placed on the hardware neighbor of already-placed qubits that minimizes total interaction-weighted distance to placed partners |
| **10** | Fill isolated/uncritical logical qubits in descending interaction-degree order using the same weighted-distance cost |
| **11** | Commit into `mapping_dict`/`reverse_mapping_dict` via the swap-based bijection builder (guarantees strict 1-to-1) |

Key design choices:
- **Default-argument capture** (`_lq=lq`) in the cost closures avoids Python's late-binding closure trap inside loops
- Centrality tiebreak (`1e-9 * phys_centrality`) keeps cost numerically stable
- Full fallback to trivial mapping when the circuit has no 2-qubit gates
