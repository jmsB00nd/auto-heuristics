**IDEA_NAME:** Critical Path Slack Inversion Cost (CPSIC)

**DESCRIPTION:** All existing heuristics weight gates by their DAG dependency count — a proxy for importance. This replaces that proxy with the actual PERT critical path slack: `slack(g) = total_span − (longest_path_to_g + longest_path_from_g)`. Gates with `slack=0` are on the critical path and infinitely bottleneck execution time. Weighting by `1/(slack+ε)` creates a principled, scheduling-theoretically grounded priority gradient that dependency count cannot express — two gates with the same depth can have very different slacks depending on convergence/divergence of paths.

**MATHEMATICAL_FORMULATION:**
```
# Precompute once per run (amortizable via topological sort O(V+E)):
slack(g) = total_dag_span − forward_depth(g) − backward_depth(g)
                                            # forward_depth from dag_dependencies_count
                                            # backward_depth from reverse pass

w(g) = 1.0 / (slack(g) + ε),   ε = 1.0   # prevents div-by-zero; ε=1 bounds max weight

W_F = Σ_{g∈F} w(g)
W_E = Σ_{g∈E} w(g) / layer_factor(g)

f_distance = Σ_{g∈F} w(g) * distance[Q1_g][Q2_g]
e_distance = Σ_{g∈E} (w(g)/layer_factor_g) * distance[Q1_g][Q2_g]

H = max_decay * (f_distance/W_F + W*(e_distance/W_E if W_E > 0 else 0))
```

**LOOP_PREVENTION_STRATEGY:** Inherits the existing `max_decay` mechanism. Additionally: because slack is a static property of the DAG structure (not the mapping), it cannot induce oscillation by itself. The weight function is bounded `[ε/(max_slack+ε), 1/ε]`, so the cost is always finite and bounded. Tie-breaking by `(swap[0]*N + swap[1]) * 1e-12` as standard.

**WHY_NOVEL:** Every known heuristic uses `(deps+1)` or `deps²` as gate importance. PERT slack is a fundamentally different quantity: it captures the *scheduling latitude* of a gate. A gate deep in the DAG with many successors may have zero slack while a gate with fewer dependencies may have high slack — yet existing heuristics treat them identically. This maps quantum routing onto operations research scheduling theory.

**IDEA_NAME:** Edge Traffic Quadratic Congestion Cost (ETQCC)

**DESCRIPTION:** Multiple gates needing to route through the same physical edge create *routing congestion* — a SWAP on that edge serves multiple purposes, but surrounding edges become temporarily inaccessible. This cost function computes, for every candidate swap, the expected *edge traffic load*: how many gate shortest-paths pass through each hardware edge under the proposed mapping. Penalizing with the L2 norm (quadratic) of the load vector rewards balanced load distribution and discourages funneling all routing through bottleneck edges.

**MATHEMATICAL_FORMULATION:**
```
# For each candidate swap, using temp_mapping_dict:
load[e] = 0 for all hardware edges e

for g in front_layer ∪ extended_layer:
    Q1, Q2 = temp_mapping[q1_g], temp_mapping[q2_g]
    path = shortest_path(Q1, Q2, backend)        # precomputed / BFS O(E)
    for each consecutive pair (u,v) in path:
        load[(min(u,v), max(u,v))] += (deps[g]+1) / layer_factor_g

congestion = Σ_e load[e]²                        # L2 norm^2, rewards balance

f_distance = Σ_{g∈F} (deps_g+1) * distance[Q1_g][Q2_g]

H = max_decay * (f_distance / |F|  +  λ * congestion / |hardware_edges|)
```
λ ∈ [0.1, 1.0] controls the congestion–distance tradeoff.

**LOOP_PREVENTION_STRATEGY:** `max_decay` prevents oscillation. Additionally: congestion is a *global* measure over all edges; flipping the same swap twice returns identical congestion scores, creating no net preference for oscillation. The quadratic term is convex, creating a unique minimum per configuration.

**WHY_NOVEL:** No existing heuristic models routing paths as edge load. All known heuristics evaluate individual gate-pair distances in isolation and sum them. This approach treats routing paths as competing for shared hardware edge bandwidth — a classical network flow concept imported into quantum routing. The quadratic penalty is standard in load balancing (inspired by JFQ / Balanced Routing literature).

**IDEA_NAME:** Multi-Scale Geometric Telescope Cost (MSGTC)

**DESCRIPTION:** The baseline uses a flat look-ahead window with uniform `1/layer_factor` discounting. This proposes a *geometric multi-resolution* sampling: instead of weighting all extended-layer gates equally by depth, sample the extended layer at exponentially spaced depth levels `{1, 2, 4, 8, …}` with weight `γ^k` (γ < 1). This creates a wavelet-like decomposition of the DAG horizon — capturing both near-term structure (high weight) and long-range alignment signals (low weight) with provably convergent total weight `1/(1-γ)`.

**MATHEMATICAL_FORMULATION:**
```
levels = [1, 2, 4, 8, 16, ...]  # geometric progression of DAG depths
γ = 0.5                          # decay ratio, Σγ^k = 1/(1-γ) = 2.0 (finite)

# Group extended_layer by depth level:
L[k] = {g ∈ extended_layer : 2^(k-1) < layer_factor_g ≤ 2^k}

e_distance = Σ_k γ^k * (1/max(|L[k]|,1)) * Σ_{g∈L[k]} (deps_g+1) * distance[Q1_g][Q2_g]

f_distance = (1/|F|) Σ_{g∈F} (deps_g+1) * distance[Q1_g][Q2_g]

H = max_decay * (f_distance + W * e_distance)
```

**LOOP_PREVENTION_STRATEGY:** `max_decay` handles oscillation. The geometric series sum is bounded `≤ 1/(1-γ)` regardless of DAG size, so no runaway scaling. Empty levels `L[k]=∅` contribute zero (handled via `max(|L[k]|, 1)` normalization). The monotone weight decay means later decisions can never dominate earlier ones, preventing over-correction.

**WHY_NOVEL:** All existing heuristics use either (a) flat discounting by `1/depth` or (b) a fixed look-ahead window. This introduces *logarithmic depth sampling* — the mathematical structure of a geometric wavelet transform. It captures the same future information but with O(log(horizon)) significant levels instead of O(horizon), making it more robust to noisy distant gates while preserving meaningful multi-scale signal.

**IDEA_NAME:** UCB-Regret Swap Aversion Cost (URSAC)

**DESCRIPTION:** Frames swap selection as a multi-armed bandit problem. Each hardware edge `e` is an "arm." After each swap, we observe a reward = (cost_before − cost_after). We accumulate *regret* for each edge: cumulative cases where the swap failed to improve (or worsened) the cost. When evaluating future swaps, add a UCB-style penalty inversely proportional to usage count — encouraging exploration of underused edges while penalizing edges with high historical regret. This is fundamentally different from OSHB (which detects cycles) and QMRP (which detects reversal): it accumulates calibrated evidence of which edges are locally unproductive.

**MATHEMATICAL_FORMULATION:**
```
# State maintained across algorithm steps:
regret[e] += max(0, cost_after - cost_before)   # only count failures
usage[e]  += 1
t          = total_swap_count + 1

# UCB exploration bonus (decaying over time):
ucb_penalty[e] = regret[e] / (usage[e] + 1)
               + β * sqrt(log(t + 1) / (usage[e] + 1))
               # β ∈ [0.01, 0.1], small to keep it as tie-breaker

# Final cost:
H = baseline_score(swap) + ucb_penalty[swap_edge]
    where baseline_score = existing f_distance/|F| + W*e_distance/|E|
```

**LOOP_PREVENTION_STRATEGY:** Regret accumulates permanently for each edge. An oscillating swap pair `(e, ē)` will have `cost_after ≈ cost_before` at each step, monotonically increasing `regret[e]` and `regret[ē]`. After K oscillations, the UCB penalty becomes so large that both edges are dominated by any other candidate. This is *stronger* than OSHB because it requires no hash comparison — the cost function itself makes oscillation self-defeating.

**WHY_NOVEL:** OSHB detects cycles via hash comparison (binary). QMRP detects reversal via physical distance direction (geometric). URSAC learns edge *quality* via accumulated reward signal (statistical). It's the only proposal grounded in online learning / regret minimization theory, which provides theoretical guarantees on cumulative exploration cost (O(√T log T) regret bound). No existing heuristic in the project uses this framework.

**IDEA_NAME:** Interaction Homomorphism Profit Cost (IHPC)

**DESCRIPTION:** A gate pair `(Q1, Q2)` is *natively resolved* if `(Q1,Q2) ∈ backend_connections` under the proposed mapping. The set of natively resolved gates is a *graph homomorphism* from the gate interaction graph into the hardware adjacency graph. This cost function rewards candidate swaps that *maximize the number of natively resolved gates* in the front + extended layer — a novel algebraic objective directly targeting the root cause of SWAP insertion (interaction graph not being a subgraph of hardware).

**MATHEMATICAL_FORMULATION:**
```
# Precomputed per swap (O(|F|+|E|)):
resolved_F = Σ_{g∈F} 1[(Q1_g, Q2_g) ∈ backend_connections] * (deps_g+1)
total_F    = Σ_{g∈F} (deps_g+1)

resolved_E = Σ_{g∈E} 1[(Q1_g, Q2_g) ∈ backend_connections] * (deps_g+1) / layer_factor_g
total_E    = Σ_{g∈E} (deps_g+1) / layer_factor_g

homomorphism_profit = resolved_F / max(total_F, 1)  +  W * resolved_E / max(total_E, 1)
                      # ∈ [0, 1+W], fully bounded, no div-by-zero

# Combine with baseline distance cost:
H = max_decay * (f_distance/|F| - λ * homomorphism_profit)
    # λ ∈ [0.5, 2.0]
```

**LOOP_PREVENTION_STRATEGY:** `max_decay`. The homomorphism profit term is strictly bounded `∈ [0, 1+W]` and does not depend on swap history, so it cannot itself introduce oscillation. When two swaps tie on distance, the homomorphism profit breaks ties deterministically based on hardware structure (not history), preventing arbitrary tie-breaking from inducing loops.

**WHY_NOVEL:** IGRB rewards *specific swaps* that immediately make one gate adjacent. IHPC rewards the *global mapping* that makes the maximum number of gates adjacent simultaneously — a fundamentally different level of abstraction. It directly measures partial graph homomorphism `G_interaction → G_hardware`, connecting quantum routing to classical graph theory. No existing heuristic frames the problem this way.

**IDEA_NAME:** Lyapunov Barrier Descent Cost (LBDC)

**DESCRIPTION:** Designs the cost function as an explicit Lyapunov function `V(mapping)` with provable convergence: `V ≥ 0`, `V = 0` only when all front-layer gates are executable, and each accepted swap *strictly* decreases `V`. The key insight is constructing `V` such that it is a *potential function* over the mapping space — the gradient of `V` points toward feasible mappings. This achieves something no existing heuristic guarantees: mathematical proof of finite termination without relying on decay or cycle detection.

**MATHEMATICAL_FORMULATION:**
```
# V(mapping) = strictly positive potential:
V(mapping) = Σ_{g∈F} (distance[Q1_g][Q2_g])²   # sum of squared distances
           + ε * Σ_{g∈E} distance[Q1_g][Q2_g] / layer_factor_g

# The squared term is key: it creates a convex, bounded-below potential.
# Each swap either (1) reduces some distance → V decreases, or
# (2) increases some distances → mark as forbidden for this state.

# Score for a candidate swap:
ΔV(swap) = V(temp_mapping) - V(current_mapping)

H = ΔV(swap) + max_decay * tiebreak_constant * (swap[0]*N + swap[1]) * 1e-12

# HARD CONSTRAINT: if no swap reduces V, enter "escape mode":
# Accept the swap with minimum ΔV (least harmful), reset decay
```

**LOOP_PREVENTION_STRATEGY:** This is the *only proposed cost function with a mathematical proof of convergence*. Since `V ≥ 0` and each accepted swap strictly decreases `V` (by construction, we only accept decreasing swaps, or the absolute minimum ΔV in escape mode), `V` cannot increase indefinitely. The sequence `V_1 ≥ V_2 ≥ ... ≥ 0` converges in finite steps. Ping-ponging is impossible: swapping back gives `V(mapping_original) > V(mapping_after_first_swap)`, so it is never selected.

**WHY_NOVEL:** No existing heuristic (in this project or in the literature) frames routing cost as a Lyapunov function with provable convergence. The squared distance construction is critical — linear distance sums can have saddle points, but quadratic sums are strictly convex and have unique minima. This bridges quantum routing to dynamical systems theory.

**IDEA_NAME:** Neighborhood-Demand Compatibility Cost (NDCC)

**DESCRIPTION:** For each *logical* qubit `q`, compute its "interaction demand set" `D(q)` = the set of physical qubits it needs to be adjacent to (based on gates in F∪E). Compare this against its actual physical adjacency set `N_H(mapping[q])`. The *compatibility* is `|D(q) ∩ N_H(mapping[q])| / |D(q)|` — the fraction of interaction needs already met by hardware adjacency. Maximize total compatibility across all active qubits. This measures *local hardware fit* of each qubit simultaneously, not just pairwise gate distance.

**MATHEMATICAL_FORMULATION:**
```
# For each active logical qubit q with temp_mapping[q] = p:
D(q)   = { temp_mapping[q'] : g=(q,q') or g=(q',q) ∈ F∪E }  # desired physical neighbors
N_H(p) = { neighbors of p in backend }                         # actual physical neighbors

met(q)   = |D(q) ∩ N_H(p)|                                    # needs already satisfied
compat(q) = met(q) / max(|D(q)|, 1)                            # ∈ [0,1], no div-by-zero

# Weighted by interaction count:
weight(q)        = |D(q)|
global_compat    = Σ_q weight(q)*compat(q) / max(Σ_q weight(q), 1)   # ∈ [0,1]

# Cost: combine baseline distance with compatibility reward:
f_distance = Σ_{g∈F} (deps_g+1) * distance[Q1_g][Q2_g] / |F|
H = max_decay * (f_distance - λ * global_compat)
```

**LOOP_PREVENTION_STRATEGY:** `max_decay`. Global compatibility is bounded `∈ [0,1]`, so the cost function cannot diverge. Oscillation is prevented because swapping two qubits and swapping them back yields identical compatibility scores — no benefit from the oscillation, so `max_decay` immediately dominates and blocks it.

**WHY_NOVEL:** All existing heuristics evaluate gate pairs `(q1,q2)` independently. NDCC evaluates each qubit's *entire local interaction neighborhood simultaneously*. A qubit adjacent to 3 of its 4 needed partners scores high even if individual pairwise distances look moderate. This captures *local hardware embeddability* — whether a qubit's interaction fan-out fits into its hardware neighborhood — which no pairwise distance metric can express.

**IDEA_NAME:** Topological Defect Annihilation Cost (TDAC)

**DESCRIPTION:** Borrowed from condensed matter physics (crystal defect theory). A gate pair `(Q1,Q2)` with `distance[Q1][Q2] > 1` is a *topological defect* in the mapping — a dislocation from the ideal state. A swap that brings a gate pair to distance 1 is an *annihilation event* (defect is eliminated). The cost function explicitly tracks defect density and rewards annihilation events with a super-linear bonus proportional to the gate's criticality — creating a "defect energy landscape" that drives the router toward defect-free configurations.

**MATHEMATICAL_FORMULATION:**
```
# Current mapping state:
defect_energy(g) = max(0, distance_before[Q1_g][Q2_g] - 1) ** 2 * (deps_g+1)

# After proposed swap (temp_mapping):
annihilation_events = { g ∈ F : distance_before[Q1_g][Q2_g] > 1
                                AND distance_after[Q1_g][Q2_g] == 1 }
annihilation_bonus  = Σ_{g∈annihilation_events} (deps_g+1)² * ANNIHILATION_GAIN

creation_events     = { g ∈ F : distance_after > distance_before }
creation_penalty    = Σ_{g∈creation_events} (distance_after-distance_before)*(deps_g+1)

# Total defect cost after swap:
defect_cost_after = Σ_{g∈F} max(0, distance_after[Q1_g][Q2_g]-1)² * (deps_g+1) / |F|

H = max_decay * (defect_cost_after - annihilation_bonus/|F| + creation_penalty/|F|)
```
`ANNIHILATION_GAIN = 3.0` (super-linear reward for complete resolution).

**LOOP_PREVENTION_STRATEGY:** `max_decay`. The squared defect energy is strictly convex and bounded below by 0. Annihilation events permanently reduce defect count (once a gate resolves, it leaves the front layer). Creation events are explicitly penalized. Oscillation would: (1) un-annihilate a previously resolved gate pair (which has left the front layer — impossible), or (2) create new defects that incur creation penalty. Both outcomes increase cost, making oscillation self-defeating.

**WHY_NOVEL:** IGRB rewards adjacency bonuses linearly. TDAC uses a physics-inspired *nonlinear* defect energy (`distance²`) and distinguishes between annihilation events (complete resolution) and partial improvement — a fundamentally different incentive structure. The physics analogy connects to Ginzburg-Landau theory where defect annihilation releases localized energy, enabling the cost landscape to have sharp, attractive basins around defect-free configurations.

**IDEA_NAME:** Causal Cone Spatial Diameter Cost (CCSDC)

**DESCRIPTION:** The *causal cone* of a front-layer gate `g` is the set of all gates transitively enabled by `g`. The *physical diameter* of this cone = the maximum pairwise hardware distance between any two qubits involved in the cone's gates. Minimizing cone diameter means related computations stay physically clustered — a global locality principle that pairwise distance cannot capture. A swap that fragments a gate's causal cone across distant hardware nodes is globally harmful even if it locally reduces one gate's distance.

**MATHEMATICAL_FORMULATION:**
```
# Precomputed once per front layer update (amortized):
for g in front_layer:
    cone(g) = BFS/DFS over dag2q from g (up to depth K = look_ahead_param)
    phys_qubits(g) = { temp_mapping[q] for h in cone(g) for q in access2q[h] }
    diameter(g) = max_{p1,p2 ∈ phys_qubits(g)} distance_matrix[p1][p2]
                  if |phys_qubits(g)| >= 2 else 0

# Cost:
cone_cost = Σ_{g∈F} (deps_g+1) * diameter(g) / |F|

# Blend with baseline:
f_distance = Σ_{g∈F} (deps_g+1) * distance[Q1_g][Q2_g] / |F|
H = max_decay * (α * f_distance + β * cone_cost)
```
`α=0.7, β=0.3`; cone BFS depth bounded by `K` for O(K×|F|) computation.

**LOOP_PREVENTION_STRATEGY:** `max_decay`. Cone diameter is symmetric (unaffected by swap direction), so swapping and un-swapping yields unchanged diameter scores — oscillation provides no diameter benefit. The diameter is bounded `[0, max_hardware_diameter]`, ensuring numerical stability. Lexicographic tie-breaking as standard.

**WHY_NOVEL:** All existing heuristics evaluate *individual gates* in isolation. CCSDC evaluates *transitive computational neighborhoods* — the physical spread of everything a gate will enable. Two gates with identical pairwise distance can have radically different cone diameters depending on whether their downstream computation is clustered or scattered on the hardware. This captures *spatial coherence of computation* — a concept from cache-aware algorithms applied to quantum routing.

**IDEA_NAME:** Distance Distribution Entropy Cost (DDEC)

**DESCRIPTION:** Rather than minimizing the *mean* distance across front-layer gates (which all existing heuristics do), this minimizes the *entropy* of the distance distribution. High-entropy distance distributions (many gates at varying distances) indicate an unstructured mapping; low-entropy distributions (gates clustered at one or two distances) indicate a well-organized mapping. Specifically, the routing should drive toward a *concentrated* distribution — either all gates adjacent (distance 1) or clustered at the nearest achievable distances.

**MATHEMATICAL_FORMULATION:**
```
# Distance histogram for front layer:
max_d = max hardware diameter
count[d] = Σ_{g∈F} (deps_g+1) * 1[distance[Q1_g][Q2_g] == d]
total     = Σ_d count[d]          # = Σ_g (deps_g+1)
p[d]      = count[d] / total      # probability mass at distance d

# Weighted Shannon entropy (lower = better organized):
H_entropy = -Σ_{d: p[d]>0} p[d] * log2(p[d])   # ∈ [0, log2(max_d)]

# Mean distance:
mean_d = Σ_d d * p[d]

# Cost: joint minimization of mean and spread:
H = max_decay * (mean_d + λ * H_entropy)
    # λ ∈ [0.1, 1.0]
```

**LOOP_PREVENTION_STRATEGY:** `max_decay`. Shannon entropy is always `≥ 0` and equals 0 only when all gates are at the same distance (perfectly organized). Entropy itself cannot cause oscillation since it's stateless (depends only on current mapping). The mean + entropy combination is bounded below and has a unique minimum at the fully-resolved configuration (all distances = 0).

**WHY_NOVEL:** Every existing heuristic minimizes the *mean* distance (first moment of distance distribution). DDEC minimizes both the *mean AND the variance/entropy* (first + second/higher moments). This is equivalent to minimizing the entire distribution, not just its center. High-variance distance distributions are harmful even at low mean — a mapping where 50% of gates are at distance 0 and 50% at distance 8 is far worse than one where all gates are at distance 4, despite identical means.

**IDEA_NAME:** Two-Swap Chain Lookahead Prefix Cost (TSCLPC)

**DESCRIPTION:** Instead of evaluating each candidate swap independently, evaluates every *pair* of sequential swaps `(s1, s2)` and assigns swap `s1` the cost of the best 2-step sequence starting with `s1`. This captures *second-order effects*: a swap that looks locally suboptimal may be optimal as a first step in a beneficial 2-swap sequence. The search over pairs is O(|candidates|²) per step but feasible since |candidates| ≤ 2×|hardware_edges| ≈ O(N) for typical quantum backends.

**MATHEMATICAL_FORMULATION:**
```
# For each candidate swap s1:
best_two_step_cost[s1] = min over all s2 ≠ s1:
    C(apply_swap(apply_swap(mapping, s1), s2))

where C(m) = baseline_cost(m) = f_distance(m)/|F| + W*e_distance(m)/|E|

# Final score for s1:
H(s1) = max_decay * best_two_step_cost[s1]
       + (1-max_decay) * C(apply_swap(mapping, s1))   # interpolate for stability

# Optimization: pre-filter s1 candidates to top-K by single-step cost
# to bound: evaluate at most K * |neighbors| two-step sequences
```

**LOOP_PREVENTION_STRATEGY:** `max_decay`. Two-step evaluation naturally prevents 1-step oscillation (a swap that immediately reverses cannot be the first step of a *best* 2-step sequence, since the second step would need to undo the first — yielding cost equal to doing nothing, which can never beat a productive swap). The decay parameter prevents the special case where two-step plans cycle with period 2.

**WHY_NOVEL:** SABRE uses a single look-ahead layer (set of future gates). This uses a *sequential swap look-ahead* — evaluating actual routing decisions, not future gates. It's analogous to 2-ply game tree search in chess, applied to SWAP selection. No existing quantum routing heuristic evaluates multi-step SWAP sequences explicitly. The key novelty is assigning swap `s1` the value of the *best continuation*, not its immediate effect.

**IDEA_NAME:** Criticality-Weighted Flow Conservation Cost (CWFCC)

**DESCRIPTION:** Models the routing problem as a *flow network*: each gate contributes `(deps+1)` units of "urgency flow" that must travel from Q1 to Q2 through the hardware graph. A candidate swap increases the capacity of its edge. The cost measures *unsatisfied flow* — the total urgency-weighted distance that cannot be immediately routed. Inspired by max-flow min-cut duality: the bottleneck in routing is the minimum cut separating gate pairs, and the cost function directly measures how close the current mapping is to that cut.

**MATHEMATICAL_FORMULATION:**
```
# For each gate g, urgency = deps[g] + 1
# Unsatisfied flow of g = urgency * distance[Q1_g][Q2_g]
# (distance = min-cost path in hardware, captures flow routing)

# "Flow deficit" = total urgency × extra hops needed:
deficit_F = Σ_{g∈F} (deps_g+1) * max(0, distance[Q1_g][Q2_g] - 1)   # swaps needed
deficit_E = Σ_{g∈E} (deps_g+1) * max(0, distance[Q1_g][Q2_g] - 1) / layer_factor_g

# Congestion-adjusted: swap edge gets temporary +1 capacity bonus
# → gates whose path uses this edge get distance reduction of 1:
benefit_F = Σ_{g∈F: swap_on_path(g)} (deps_g+1)
benefit_E = Σ_{g∈E: swap_on_path(g)} (deps_g+1) / layer_factor_g

# swap_on_path(g) = True if the edge being swapped lies on a shortest path from Q1_g to Q2_g

H = max_decay * (deficit_F/|F| - λ*benefit_F/|F|
               + W*(deficit_E/max(|E|,1) - λ*benefit_E/max(|E|,1)))
```

**LOOP_PREVENTION_STRATEGY:** `max_decay`. Flow deficit is non-negative and decreases as gates get closer. `swap_on_path(g)` is a static Boolean property of the hardware topology (not swap history), so it cannot induce oscillation. Once deficit_F = 0 (all front-layer gates executable), the algorithm terminates normally.

**WHY_NOVEL:** Existing heuristics measure distances and sum them. CWFCC explicitly models *which hardware edge serves which gate's routing path*, turning SWAP selection into a benefit/capacity question: "does this edge carry urgency flow?" **IDEA_NAME:** Hamming Distance to Target Permutation Cost (HDTPC)

**DESCRIPTION:** For each gate `g ∈ F`, compute the *ideal physical assignment* of its two qubits: the pair of adjacent hardware nodes that minimizes the total cost for all front-layer gates if we could freely reassign them. The current mapping is a permutation; the ideal is another permutation. The *Hamming distance* between these permutations (number of qubits not in their ideal positions) measures how far the router is from the locally optimal state — a fundamentally combinatorial measure distinct from continuous distance sums.

**MATHEMATICAL_FORMULATION:**
```
# Precompute ideal_assignment by solving a min-cost matching:
# For each gate g∈F, enumerate all adjacent hardware pairs (p1,p2):
# ideal_pair(g) = argmin_{(p1,p2)∈hardware_edges} distance[Q1_g][p1] + distance[Q2_g][p2]
#                 (greedy per-gate; full joint optimal is NP-hard, use greedy approximation)

ideal_physical[q] = ideal_pair(g)[i]   for each logical qubit q in gate g

# Hamming distance:
hamming = Σ_q 1[temp_mapping[q] ≠ ideal_physical[q]] * interaction_weight[q]
          where interaction_weight[q] = Σ_{g: q∈g} (deps_g+1)

# Blend with f_distance:
f_distance = Σ_{g∈F} (deps_g+1) * distance[Q1_g][Q2_g] / |F|
H = max_decay * (f_distance/|F| + μ * hamming / total_weight)
```

**LOOP_PREVENTION_STRATEGY:** `max_decay`. `ideal_physical` is recomputed per candidate swap independently, so it doesn't carry oscillation-inducing state. Hamming distance ≥ 0 and equals 0 when the mapping matches the ideal. The interaction-weighted Hamming distance has a unique minimum (the ideal mapping), creating a clear convergence target.

**WHY_NOVEL:** All existing heuristics work with *continuous* distance measures. Hamming distance is a *combinatorial* dissimilarity — it counts mismatches rather than measuring magnitude. This creates a fundamentally different cost landscape with a discrete structure. The concept of computing a "target permutation" and measuring mapping distance to it is borrowed from combinatorial optimization (permutation groups, Cayley graphs) and has not appeared in quantum routing heuristics.

**IDEA_NAME:** Cooperative Qubit Interaction Density Cost (CQIDC)

**DESCRIPTION:** Models qubit interactions as a *density field* over the hardware graph. Each gate `g` creates a "density blob" centered between its two required qubits, weighted by criticality. The total interaction density at each hardware node is the sum of all blobs. A candidate swap is good if it moves high-demand qubits toward regions of high interaction density. This is inspired by *mean-field theory* in statistical physics — each qubit moves in the average field created by all other interactions.

**MATHEMATICAL_FORMULATION:**
```
# Interaction density at physical node p:
ρ(p) = Σ_{g∈F∪E} (deps_g+1) / layer_factor_g
            * exp(-α * min(distance[p][Q1_g], distance[p][Q2_g]))
       # Gaussian-like decay; α controls locality; exp(-α*0)=1 max

# For each logical qubit q with proposed mapping temp_mapping[q] = p:
demand(q) = Σ_{g: q∈g, g∈F∪E} (deps_g+1) / layer_factor_g   # urgency of q's gates

# Alignment: how well does q sit in a high-density region?
alignment(q) = demand(q) * ρ(temp_mapping[q])

# Cost: reward high alignment, penalize low alignment:
H = max_decay * (f_distance/|F| - λ * Σ_q alignment(q) / max(Σ_q demand(q), 1))
```

**LOOP_PREVENTION_STRATEGY:** `max_decay`. The density field `ρ(p)` is recomputed from the *proposed mapping* (temp_mapping), so oscillation would create the same field repeatedly, providing no increasing alignment benefit. The exponential decay ensures `ρ(p) ∈ (0, N]` (bounded), preventing divergence. The cost is bounded below by `f_distance - λ*(1+W)`.

**WHY_NOVEL:** No existing heuristic creates a continuous *field* over the hardware topology. All existing approaches reason about individual gate pairs or single qubits in isolation. The mean-field approach allows every qubit to simultaneously "sense" the average demand from all other interactions — a cooperative effect that is fundamentally different from pairwise distance evaluation. The exponential spatial decay parameter `α` also provides a smooth locality-globality tradeoff not present in any existing heuristic.

**IDEA_NAME:** Adaptive Concavity Cost (ACC2)

**DESCRIPTION:** The baseline uses a *linear* sum of distances. This proposes replacing the linear aggregation with a *concave* function `f(d) = log(1 + d)` (or `√d`), changing the cost landscape fundamentally. Concave aggregation *penalizes outliers less than linear* — it prioritizes reducing large distances even at the expense of slightly increasing small ones. This creates a "leveling" effect: large distance gates dominate, and small distance gates are de-prioritized. This is in direct contrast to quadratic (convex) aggregation which over-penalizes small errors.

**MATHEMATICAL_FORMULATION:**
```
# Replace linear distance with log-compressed distance:
f_compressed = Σ_{g∈F} (deps_g+1) * log1p(distance[Q1_g][Q2_g]) / |F|
e_compressed = Σ_{g∈E} (deps_g+1) * log1p(distance[Q1_g][Q2_g]) / (layer_factor_g * max(|E|,1))

# The log1p function:
# - log1p(0) = 0   (adjacent gates cost nothing — exactly right)
# - log1p(1) = 0.693 (one hop away)
# - log1p(d) ≈ log(d) for large d (severely non-linear penalty for outliers)
# - No div-by-zero ever (log1p defined ∀d ≥ 0)

H = max_decay * (f_compressed + W * e_compressed)
```

**LOOP_PREVENTION_STRATEGY:** `max_decay`. `log1p(d)` is monotone increasing in `d`, so minimizing `H` still drives distances toward 0. The concave shape means the *marginal benefit* of reducing a distance from 5→4 is greater than reducing 2→1, creating pressure to resolve the most "stuck" gate pairs first. This *reduces oscillation* relative to linear/quadratic by avoiding the situation where one gate's improvement alternately creates and destroys another gate's adjacency.

**WHY_NOVEL:** All existing heuristics use linear distance (`d`) or quadratic (`d²`) aggregation. The mathematical properties of concave vs. convex aggregation create fundamentally different optimization landscapes. Concave aggregation (submodular-like) is extensively studied in combinatorial optimization (submodular maximization, robust optimization), but its application to quantum routing distance aggregation is novel. It changes which swaps are optimal — favoring resolving stuck high-distance pairs over polishing near-adjacent pairs.

**NOVELTY_SCORE:** 7
**PROBABILITY_SCORE:** 8
**EFFORT_SCORE:** 9
