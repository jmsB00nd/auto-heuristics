## Analysis of MSGTC

**Strengths:**
- Geometric decay (γ^k) gives bounded, principled weighting over depth
- Per-bucket normalization prevents large far-layer buckets from dominating
- Dependency weighting prioritizes critical-path gates

**Key weaknesses:**
1. **Constant bias in distance**: Using raw `dist` includes an offset of 1 per gate. A gate with `dist=1` is *already executable* (0 swaps needed), yet contributes 1 to cost. The true swap count is `dist - 1`, and removing this bias changes the relative ranking between swaps, especially when dependency weights vary.
2. **Coarse bucketing loses precision near the front**: `bit_length()` groups depths 3-4 together, 5-8 together, etc. For nearby extended layers (depth 2, 3) where the information is most reliable, we lose granularity exactly where it matters most.
3. **Per-bucket normalization vs. total-weight normalization**: Averaging within each bucket treats a bucket with 1 gate and one with 100 gates equally. A proper weighted average (divide by Σγ^d) is more principled.

## Evolution Strategy: Option A (Targeted Refinement)

Three surgical changes:
1. Replace `dist` with `max(0, dist - 1)` — count actual remaining swaps, not raw distance
2. Replace coarse bit-length bucketing with **continuous per-gate geometric decay** γ^(d-1)
3. Normalize extended layer by **total geometric weight** Σγ^(d-1), not per-bucket

```python
def qlosure_poly_heuristic(self, swap_gate):
    gamma = 0.55    # continuous per-depth decay; slightly less aggressive than MSGTC's 0.5
    W = 0.4         # extended-layer weight

    front_layer_size = max(len(self.front_layer), 1)
    max_decay = max(self.decay_parameter[swap_gate[0]], self.decay_parameter[swap_gate[1]])

    # Front layer: dependency-weighted remaining swap count
    # dist=1 -> adjacent, 0 swaps needed; dist=d -> d-1 swaps needed
    f_cost = 0.0
    for g in self.front_layer:
        q1, q2 = self.access2q[g]
        Q1, Q2 = self.temp_mapping_dict[q1], self.temp_mapping_dict[q2]
        deps = self.dag_dependencies_count[g]
        remaining = max(0.0, self.distance_matrix[Q1][Q2] - 1)
        f_cost += (deps + 1) * remaining
    f_cost /= front_layer_size

    # Extended layer: continuous geometric decay per gate (no coarse bucketing)
    # Normalize by total geometric weight for a properly-scaled weighted average
    e_cost = 0.0
    e_weight_total = 0.0
    for g in self.extended_layer:
        q1, q2 = self.access2q[g]
        Q1, Q2 = self.temp_mapping_dict[q1], self.temp_mapping_dict[q2]
        layer_factor = self.extended_layer_index.get(g, 0) + 1
        deps = self.dag_dependencies_count[g]
        remaining = max(0.0, self.distance_matrix[Q1][Q2] - 1)
        w = gamma ** (layer_factor - 1)
        e_cost += w * (deps + 1) * remaining
        e_weight_total += w

    if e_weight_total > 0:
        e_cost /= e_weight_total

    H = max_decay * (f_cost + W * e_cost)
    return H
```

**Why this should improve on MSGTC (419.38):**

- `dist - 1` removes the constant-per-gate bias that distorts relative swap rankings when dependency weights are non-uniform. A front-layer gate at `dist=1` (executable!) now contributes exactly 0 cost — correctly signaling the swap has already done its job for that gate.
- Continuous γ^(d-1) decay gives full precision at depths 2 and 3 where predictive power is highest, instead of grouping them into the same coarse bucket.
- Total-weight normalization (`/ Σγ^d`) treats the extended layer as a proper weighted average rather than a sum of bucket averages, which is more stable when the number of gates per depth varies.
