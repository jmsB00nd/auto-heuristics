**IDEA_NAME:** Transitive-Closure Proximity Bipartite Matching

**DESCRIPTION:** Build a logical qubit proximity matrix P_L where P_L[i][j] = total transitive dependency count between qubit i and qubit j (summed over all gates that involve both). Build a hardware proximity matrix P_H where P_H[i][j] = 1/distance_matrix[i][j] (or 0 if i==j). Solve a minimum-cost bipartite assignment using the Hungarian algorithm minimizing Σ |P_L[i][j] - P_H[f(i)][f(j)]| across all pairs, where f is the logical-to-physical assignment.

**ALGORITHMIC_APPROACH:**
1. Extract logical qubits from `self.access`
2. For each pair of logical qubits (i,j), compute proximity as Σ `dag_dependencies_count[g]` for all gates g involving both i and j
3. Build normalized hardware proximity from `self.distance_matrix`
4. Formulate cost matrix C[i][p] = Σ_j |P_L[i][j] - P_H[p][hardware_neighbor(j)]| (approximated greedily per pair)
5. Apply `scipy.optimize.linear_sum_assignment` for exact O(n³) Hungarian matching
6. Map unused physical qubits to remaining logical qubits arbitrarily

**COLLISION_PREVENTION:** `linear_sum_assignment` returns a strict 1-to-1 permutation by construction. Unused logical qubits (ancilla) get uniquely assigned to remaining physical slots via set difference.

**WHY_NOVEL:** Existing SABRE/NOISE-ADAPTIVE use local heuristics or random restarts. This directly leverages the precomputed transitive closure (already available as `dag_dependencies_count`) to encode the full DAG-weighted interaction profile into a global assignment problem, rather than greedy front-layer lookahead.

**NOVELTY_SCORE:** 7
**PROBABILITY_SCORE:** 8
**EFFORT_SCORE:** 8
**FEASIBILITY_SCORE:** 10
**AVERAGE_SCORE:** 8.3

**IDEA_NAME:** Critical-Path Backbone Spine Embedding

**DESCRIPTION:** Identify the longest weighted path in the DAG (the critical path), treating it as a "spine" of the circuit. Find the longest simple path in the hardware graph. Map the critical path qubits onto the hardware spine in order. Then attach remaining logical qubits to the nearest available physical qubit adjacent to their closest already-placed neighbor.

**ALGORITHMIC_APPROACH:**
1. Compute DAG critical path using topological sort + DP on `successors2q` with `dag_dependencies_count` as weights
2. Extract unique logical qubits in critical-path gate order
3. Find longest path in hardware: BFS/DFS on `self.backend`, using diameter endpoints as endpoints
4. Assign critical-path qubits along hardware spine (zip)
5. For remaining logical qubits sorted by their total gate frequency: find the already-placed qubit they interact with most, assign to nearest free physical neighbor via BFS

**COLLISION_PREVENTION:** Use a `placed_physical = set()` tracking set. Each greedy attachment step only considers physical qubits not in `placed_physical`. Final assignment is a bijection since each step consumes exactly one physical slot.

**WHY_NOVEL:** No existing placement algorithm explicitly extracts the DAG critical path as a structural backbone and aligns it with the hardware graph diameter path. This embeds the most time-critical computation onto the most connected hardware corridor.

**NOVELTY_SCORE:** 8
**PROBABILITY_SCORE:** 8
**EFFORT_SCORE:** 7
**FEASIBILITY_SCORE:** 10
**AVERAGE_SCORE:** 8.3

**IDEA_NAME:** Spectral Laplacian Procrustes Co-Embedding

**DESCRIPTION:** Compute the normalized graph Laplacian of the circuit interaction graph (edges weighted by 2-qubit gate count) and the hardware graph Laplacian. Extract the top-k eigenvectors of each (k = ceil(log2(n_qubits))). Apply the orthogonal Procrustes problem to find the rotation matrix R that best aligns the circuit embedding to the hardware embedding. Assign logical qubit i to the physical qubit whose embedded coordinate is nearest after applying R, resolving ties via augmenting path.

**ALGORITHMIC_APPROACH:**
1. Build weighted circuit adjacency: `W_c[i][j]` = number of 2-qubit gates between logical qubits i, j (from `self.access`)
2. Compute circuit Laplacian `L_c = D_c - W_c`, extract eigenvectors `V_c ∈ R^{n_logical × k}`
3. Build hardware Laplacian from `self.backend`, extract eigenvectors `V_h ∈ R^{n_physical × k}`
4. Subsample `V_h` to `n_logical` rows (highest-degree physical qubits)
5. Solve Procrustes: `R = argmin ||V_c - V_h_sub R||_F` via SVD: `U,S,Vt = svd(V_h_sub.T @ V_c)`, `R = U @ Vt`
6. For each logical qubit i, assign to physical qubit `argmin_p ||V_c[i] - V_h[p]R||`
7. Resolve assignment conflicts via greedy augmenting (prefer closer matches first)

**COLLISION_PREVENTION:** After spectral assignment, resolve conflicts by sorting all (logical, physical, distance) triples, greedily assigning in order of increasing distance, skipping already-used physical qubits.

**WHY_NOVEL:** Procrustes alignment of graph spectral embeddings has been used in shape matching and network alignment but never for quantum circuit placement. It exploits global topological structure of both graphs simultaneously rather than local greedy heuristics.

**NOVELTY_SCORE:** 9
**PROBABILITY_SCORE:** 6
**EFFORT_SCORE:** 6

**IDEA_NAME:** DAG-Layer-Stratified Topology Fill

**DESCRIPTION:** Compute the earliest possible execution layer for each logical qubit (the minimum DAG depth at which the qubit first participates in a 2-qubit gate). Group qubits into execution strata. Choose a seed physical qubit (highest degree in `self.backend`). Assign the first stratum to the seed and its neighbors, the second stratum to the next BFS frontier of the hardware, etc.

**ALGORITHMIC_APPROACH:**
1. For each logical qubit q, compute `earliest_layer[q]` = min depth of first 2-qubit gate involving q (topological BFS on DAG)
2. Sort logical qubits by `earliest_layer` ascending; break ties by total 2-qubit gate count (descending)
3. BFS on hardware starting from highest-degree physical qubit: produce ordered list `hw_order`
4. Zip sorted logical qubits with `hw_order[0:n_logical]`
5. Remaining physical qubits take any unmapped logical qubits

**COLLISION_PREVENTION:** BFS over hardware generates each physical qubit exactly once. Zip assignment is inherently injective. Final mapping is a bijection since |hw_order| ≥ n_logical.

**WHY_NOVEL:** Existing approaches ignore when qubits become active in the circuit schedule. By aligning circuit temporal activation order with hardware BFS depth, early-critical qubits land near the hardware core while late-activating qubits sit on the periphery where SWAP overhead matters less.

**NOVELTY_SCORE:** 7
**PROBABILITY_SCORE:** 8
**EFFORT_SCORE:** 9
**FEASIBILITY_SCORE:** 10
**AVERAGE_SCORE:** 8.5

**IDEA_NAME:** Interaction-Frequency Min-Cost Bipartite Matching

**DESCRIPTION:** Build a qubit interaction frequency matrix F where F[i][j] = number of 2-qubit gates between logical qubits i and j. Define assignment cost C[logical_q][phys_q] = Σ_{j ≠ i} F[i][j] × distance_matrix[phys_q][phys_candidate_j] where phys_candidate_j is optimistically estimated. Solve via Hungarian algorithm with an iterative refinement: assign in rounds, recomputing costs after each assignment using already-fixed mappings.

**ALGORITHMIC_APPROACH:**
1. Scan `self.access` to build F[i][j] for all 2-qubit gate pairs
2. For each logical qubit i, compute `interaction_weight[i]` = Σ_j F[i][j]
3. Round 1: Sort logical qubits by `interaction_weight` descending. Compute C[i][p] = Σ_{j already mapped} F[i][j] × distance_matrix[p][mapping[j]] + Σ_{j not mapped} F[i][j] × expected_distance (use mean hardware distance for unmapped)
4. Assign greedily: pick (i, p) = argmin C[i][p] over unassigned pairs, fix it, update costs
5. Repeat until all logical qubits assigned

**COLLISION_PREVENTION:** A `used_physical = set()` is maintained. Each greedy selection removes the chosen physical qubit from future consideration. Exactly n_logical assignments are made, one per logical qubit.

**WHY_NOVEL:** Standard bipartite matching for placement uses static cost matrices. This uses an iterative greedy matching with dynamic cost updates conditioned on already-committed assignments, approximating the joint optimization without exponential complexity.

**NOVELTY_SCORE:** 6
**PROBABILITY_SCORE:** 8
**EFFORT_SCORE:** 8
**FEASIBILITY_SCORE:** 10
**AVERAGE_SCORE:** 8.0

**IDEA_NAME:** Fiedler-Vector Recursive Bisection Alignment

**DESCRIPTION:** Recursively bisect the logical qubit set using the Fiedler vector (second eigenvector of the circuit Laplacian). Simultaneously bisect the hardware graph using its Fiedler vector. Recursively align the two bisections until each partition contains ≤ 1 logical qubit. The terminal pairing defines the initial mapping.

**ALGORITHMIC_APPROACH:**
1. Build weighted circuit Laplacian from interaction frequencies
2. Compute Fiedler vector: `v = eigenvector(L_c, second_smallest_eigenvalue)`
3. Split logical qubits: `left_logical = {q: v[q] < median(v)}`, `right_logical = complement`
4. Compute hardware Fiedler vector from `self.backend` edges
5. Split hardware: `left_hw = {p: v_h[p] < median(v_h)}`, `right_hw = complement`
6. Recursively bisect `(left_logical, left_hw)` and `(right_logical, right_hw)`
7. Base case: when |logical_partition| == 1, assign the single logical qubit to the best-degree physical qubit in the hardware partition

**COLLISION_PREVENTION:** Each recursion level partitions disjoint sets. Terminal assignments are 1-to-1 by construction since each recursion peels off exactly one logical qubit. Physical qubits in hardware partitions that exceed logical qubits are simply unused.

**WHY_NOVEL:** Recursive spectral bisection is classic in VLSI placement (Kernighan-Lin) but has never been applied to quantum placement by bisecting both the circuit graph and hardware graph simultaneously and aligning the resulting partition trees.

**NOVELTY_SCORE:** 9
**PROBABILITY_SCORE:** 7
**EFFORT_SCORE:** 6
**FEASIBILITY_SCORE:** 9
**AVERAGE_SCORE:** 7.8

**IDEA_NAME:** Resistance Distance Matrix Matching

**DESCRIPTION:** Compute the effective electrical resistance between every pair of nodes in both the circuit interaction graph (as a resistor network) and the hardware graph. Use the resistance distance as a proximity metric. Apply min-cost bipartite matching where cost = sum of squared differences between logical resistance distances and physical resistance distances.

**ALGORITHMIC_APPROACH:**
1. Build circuit weighted adjacency W_c, compute Laplacian L_c
2. Compute pseudo-inverse `L_c_pinv = np.linalg.pinv(L_c)` 
3. Resistance distance: `R_c[i][j] = L_c_pinv[i][i] + L_c_pinv[j][j] - 2*L_c_pinv[i][j]`
4. Repeat for hardware Laplacian L_h (unweighted, from `self.backend`)
5. Assignment cost: `C[i][p] = Σ_j min_{q: j→q fixed} (R_c[i][j] - R_h[p][q])²`
6. Use iterative greedy assignment (as in Interaction-Frequency) or exact Hungarian for small circuits

**COLLISION_PREVENTION:** Same iterative greedy assignment with `used_physical` set. Exact Hungarian via `scipy.optimize.linear_sum_assignment` for circuits with ≤ 50 qubits.

**WHY_NOVEL:** Effective resistance captures global graph structure including paths of all lengths, unlike shortest-path distance. Matching resistance distance profiles encodes the full commute-time geometry of both graphs simultaneously. Not previously applied to quantum placement.

**NOVELTY_SCORE:** 9
**PROBABILITY_SCORE:** 6
**EFFORT_SCORE:** 6
**FEASIBILITY_SCORE:** 9
**AVERAGE_SCORE:** 7.5

**IDEA_NAME:** Two-Phase Anchor-BFS Placement

**DESCRIPTION:** Phase 1 (Anchor Selection): Identify the top-k logical qubits by total weighted interaction (k = sqrt(n_logical)). Map each anchor to a unique high-degree, well-separated physical qubit. Phase 2 (Satellite Assignment): For each remaining logical qubit, identify its most frequently interacting already-placed neighbor. Assign it to the closest available physical qubit to that neighbor's physical location.

**ALGORITHMIC_APPROACH:**
1. Build F[i][j] from `self.access` (2-qubit gate count per pair)
2. Rank logical qubits by `Σ_j F[i][j]` → top-k are anchors
3. For anchor placement: sort hardware qubits by degree descending. Assign anchor_0 to top-degree hw qubit. Each subsequent anchor assigned to the high-degree hw qubit maximally far from all already-placed anchors (using `distance_matrix`)
4. Build priority queue of remaining logical qubits sorted by max(F[i][j]) for j in already-placed
5. Pop each, find best-interacting placed neighbor n*, BFS from `mapping[n*]` on hardware to find nearest free physical qubit
6. Assign and mark as placed

**COLLISION_PREVENTION:** `assigned_physical = set()`. BFS in step 5 iterates outward, skipping qubits in `assigned_physical`. Since hardware has ≥ n_logical qubits, BFS always terminates with a valid free slot.

**WHY_NOVEL:** Two-phase anchor strategies exist in VLSI but the combination of (1) interaction-weighted anchor selection, (2) hardware degree + max-spread anchor placement, and (3) BFS-based satellite attachment using per-qubit interaction profiles is not present in quantum compilation literature.

**NOVELTY_SCORE:** 7
**PROBABILITY_SCORE:** 9
**EFFORT_SCORE:** 9
**FEASIBILITY_SCORE:** 10
**AVERAGE_SCORE:** 8.8

**IDEA_NAME:** Multi-Level Graph Coarsening Placement

**DESCRIPTION:** Iteratively coarsen the circuit interaction graph by merging the highest-interaction qubit pairs into super-nodes. Find a placement for the coarsened graph (trivially or by degree matching). Then uncoarsen level by level, splitting each super-node and placing the two children in the hardware neighborhood of the super-node's assigned location, choosing the best local arrangement.

**ALGORITHMIC_APPROACH:**
1. Build circuit interaction graph G_c with edge weight = F[i][j]
2. Coarsening: repeat while |V| > 4: find max-weight edge (i,j), merge into super-node s with weight = F[i][j] + inherited edges
3. Bottom-level placement: assign coarsened graph (≤ 4 nodes) to hardware by exhaustive check of 4! = 24 permutations
4. Uncoarsening: split super-node s → (i, j). Assign i to s's current physical location. BFS in hardware for nearest free qubit for j. Optionally swap i/j if swapping reduces local interaction cost
5. Local refinement after each uncoarsening: check if swapping recently placed pair with any neighbor reduces Σ F[i][j] × dist[map(i)][map(j)]

**COLLISION_PREVENTION:** At uncoarsening, j's placement uses BFS from s's location with `assigned_physical` guard. The bottom-level exhaustive search is guaranteed bijective for 4 nodes. Each refinement swap exchanges two already-assigned entries preserving bijectivity.

**WHY_NOVEL:** METIS-style multilevel coarsening is standard for graph partitioning but has not been applied to quantum initial placement. The key novelty is using gate-interaction weight as the coarsening criterion, combined with hardware-aware local refinement during uncoarsening.

**NOVELTY_SCORE:** 8
**PROBABILITY_SCORE:** 7
**EFFORT_SCORE:** 6
**FEASIBILITY_SCORE:** 9
**AVERAGE_SCORE:** 7.5

**IDEA_NAME:** Simulated Annealing with DAG-Lookahead Energy

**DESCRIPTION:** Start from a degree-sorted initial mapping. Run simulated annealing where each step proposes a random swap of two logical-to-physical assignments. The energy function evaluates the expected routing cost using the same weighted distance sum as `qlosure_poly_heuristic` but applied over the entire circuit (or a large sample of front-layer + extended layer gates), without actually executing any routing.

**ALGORITHMIC_APPROACH:**
1. Initial state: sort logical qubits by total interaction weight, assign to hardware qubits sorted by degree (descending)
2. Precompute a "static front layer" = all gates whose predecessors in DAG are 0 (initial front layer)
3. Energy E = Σ_{g in static_front_layer} deps(g) × distance_matrix[map(q1)][map(q2)] + W × Σ_{g in extended_layer} ...  (mirrors `qlosure_poly_heuristic` structure)
4. SA loop (T from 1.0 → 0.01, N_steps = min(1000, 10 × n_logical²)):
   - Propose: swap map(i) ↔ map(j) for random i, j
   - ΔE = new_E - old_E
   - Accept if ΔE < 0 or random() < exp(-ΔE/T)
5. Return best mapping found

**COLLISION_PREVENTION:** Only swap operations are used (no reassignment), which preserve bijectivity. The mapping is always a permutation of physical qubits.

**WHY_NOVEL:** SA for placement exists in VLSI. What's novel here is using the exact same energy function (with transitive closure weights and layered extended-set structure) that the routing heuristic uses, making the placement phase directly optimize for the routing cost metric.

**NOVELTY_SCORE:** 6
**PROBABILITY_SCORE:** 8
**EFFORT_SCORE:** 7
**FEASIBILITY_SCORE:** 10
**AVERAGE_SCORE:** 7.8

**IDEA_NAME:** BFS-Synchronized Dual-Graph Traversal

**DESCRIPTION:** Run BFS simultaneously on the circuit interaction graph and the hardware graph. At each step, match the current BFS frontier of circuit qubits to the current BFS frontier of hardware qubits by solving a local min-cost matching on the frontier pairs. This synchronizes the structural exploration of both graphs, assigning logically "close" qubits to physically "close" hardware locations.

**ALGORITHMIC_APPROACH:**
1. Select seed logical qubit: highest total interaction weight. Select seed hardware qubit: highest degree
2. `logical_queue = [seed_logical]`, `hw_queue = [seed_hw]`
3. While unassigned logical qubits remain:
   a. Pop current BFS frontier (all qubits at current BFS depth) from both queues
   b. If |logical_frontier| != |hw_frontier|: pad smaller frontier by pulling next-level nodes
   c. Solve local min-cost matching between logical_frontier and hw_frontier using `scipy.optimize.linear_sum_assignment` with cost = interaction weight to already-placed neighbors
   d. Add unvisited neighbors of assigned qubits to next BFS level in both graphs
4. Assign matched pairs

**COLLISION_PREVENTION:** BFS over hardware visits each node exactly once. The local matching within each frontier is a bijection. A `visited_hw = set()` prevents double-assignment. Frontier size mismatches are handled by pulling ahead in the larger graph.

**WHY_NOVEL:** Synchronized BFS matching between two graphs for placement is inspired by graph isomorphism algorithms but operates on weighted BFS frontiers with local matching, trading optimality for polynomial time. This structure-aware traversal alignment is novel in the quantum compilation context.

**NOVELTY_SCORE:** 8
**PROBABILITY_SCORE:** 7
**EFFORT_SCORE:** 7

**IDEA_NAME:** Qubit Temporal Co-Occurrence Embedding

**DESCRIPTION:** Process the topologically sorted gate sequence in a sliding window of size W. Build a co-occurrence matrix M where M[i][j] += 1/distance_in_circuit(i,j) for each window containing both logical qubits i and j. This encodes temporal proximity: qubits that interact in close temporal succession have high co-occurrence. Apply PCA on M to get 2D/3D coordinates for each logical qubit. Assign to hardware qubits using nearest-neighbor matching in the embedded space against hardware Laplacian eigenvector coordinates.

**ALGORITHMIC_APPROACH:**
1. Topological sort of gates from `self.access` using `dag_predecessors2q`
2. Sliding window of size W = max(10, n_logical//2) over sorted gate sequence
3. For each window: for each pair (i,j) of qubits appearing in the window, `M[i][j] += 1/(1 + gate_distance)` where gate_distance = position difference in window
4. `M = M + M.T` (symmetrize)
5. PCA on M → 2D coordinates `coords_logical`
6. Hardware: compute 2D Laplacian eigenmap coordinates `coords_hw` for physical qubits
7. Nearest-neighbor assignment: for each logical qubit (sorted by total interaction weight), assign to nearest available hardware qubit in 2D embedded space

**COLLISION_PREVENTION:** Greedy nearest-neighbor with `assigned_hw = set()`. Sort by interaction weight to prioritize high-activity qubits getting their best physical match first. Always a valid bijection since hardware has ≥ n_logical qubits.

**WHY_NOVEL:** Sliding window temporal co-occurrence is borrowed from NLP (word2vec-style) and applied to gate sequences to create circuit-aware qubit embeddings. Matching these temporal embeddings to hardware spectral embeddings is a cross-domain technique not previously applied to initial placement.

**IDEA_NAME:** Community-Clique Hardware Density Matching

**DESCRIPTION:** Detect communities in the circuit interaction graph using modularity-maximizing clustering (Louvain). For each community, compute its internal edge density. Find a corresponding dense connected subgraph in the hardware graph of the same size. Assign the community to that hardware subgraph, matching intra-community interaction structure to intra-subgraph hardware connectivity. Run Hungarian matching within each community-subgraph pair.

**ALGORITHMIC_APPROACH:**
1. Build circuit interaction graph G_c with weights F[i][j]
2. Run Louvain community detection (`python-louvain` or `networkx.community.louvain_communities`) to get communities C_1, ..., C_k
3. For each community C_t of size s_t: enumerate connected hardware subgraphs of size s_t by BFS from each physical qubit (feasible for s_t ≤ 15 with BFS pruning)
4. Score each (C_t, hardware_subgraph) pair: score = Σ_{(i,j) in C_t edges} F[i][j] × [is_edge_in_hw_subgraph(map(i), map(j))]
5. Assign best hardware subgraph to each community greedily (largest community first, no overlap)
6. Within each community-subgraph pair: solve min-cost matching with `linear_sum_assignment`

**COLLISION_PREVENTION:** Hardware subgraph assignment is greedy with a global `used_hw_qubits` set preventing overlap. Within-community Hungarian matching is a bijection. Remaining unmapped qubits after all communities are assigned get BFS-nearest free physical qubits.

**WHY_NOVEL:** Community-aware placement exists in VLSI but the combination of interaction-weighted Louvain community detection, hardware subgraph density scoring, and two-level matching (community→subgraph, then intra-community Hungarian) is novel for quantum circuit placement.

**NOVELTY_SCORE:** 7
**PROBABILITY_SCORE:** 7

**IDEA_NAME:** Dependency-Weighted Centrality Alignment

**DESCRIPTION:** Compute multiple centrality measures for each logical qubit in the circuit interaction graph: degree centrality, betweenness centrality, and eigenvector centrality (weighted by F[i][j]). Compute the same centrality measures for each physical qubit in the hardware graph. Build a composite centrality score vector for each node. Assign logical qubits to physical qubits by minimizing the L2 distance between their centrality score vectors using Hungarian matching.

**ALGORITHMIC_APPROACH:**
1. Build weighted circuit interaction graph from `self.access`
2. Compute per-logical-qubit: `deg_c[q]`, `betw_c[q]`, `eig_c[q]` using `networkx`
3. Build hardware graph from `self.backend` edges
4. Compute per-physical-qubit: `deg_h[p]`, `betw_h[p]`, `eig_h[p]`
5. Normalize each centrality vector to [0,1] range independently
6. For each logical qubit i and physical qubit p: `C[i][p] = ||[deg_c[i], betw_c[i], eig_c[i]] - [deg_h[p], betw_h[p], eig_h[p]]||_2`
7. Run `scipy.optimize.linear_sum_assignment(C[:n_logical, :])` on the n_logical × n_physical submatrix

**COLLISION_PREVENTION:** `linear_sum_assignment` returns strict 1-to-1 assignment. If n_physical > n_logical, the extra columns are simply unassigned. If n_physical < n_logical (impossible per quantum hardware), raise an error.

**WHY_NOVEL:** Single-centrality alignment (degree to degree) is known but crude. Using a multi-dimensional centrality vector and matching with L2 distance captures the full structural role of each qubit in both graphs simultaneously, providing a richer structural homomorphism than single-metric approaches.

**NOVELTY_SCORE:** 6
**PROBABILITY_SCORE:** 7
**EFFORT_SCORE:** 8

**IDEA_NAME:** Forward-Simulation Greedy Placement

**DESCRIPTION:** Simulate the first K routing steps (without committing) for multiple candidate initial mappings. Start with the degree-sorted baseline. Iteratively improve by identifying which logical-physical pair, if swapped in the initial mapping, most reduces the simulated SWAP count over the first K gates. Apply the best swap and repeat.

**ALGORITHMIC_APPROACH:**
1. Start: baseline mapping (logical qubit i → physical qubit sorted_by_degree[i])
2. Simulate K gates from front layer using a lightweight version of `execute_algorithm` (no circuit updates, no tqdm)
3. Record swap count S_0
4. For each candidate swap (i_logical, j_logical) in initial mapping (O(n²) pairs):
   a. Swap their physical assignments in a temp mapping
   b. Re-simulate K gates → get S_swap
5. Apply swap with best (S_0 - S_swap) improvement if positive
6. Repeat for M iterations (M = min(n_logical, 20)) or until no improvement
7. Final mapping = accumulated swaps applied to baseline

**COLLISION_PREVENTION:** Only swap operations on the mapping (exchanging two physical qubit assignments) are used at every step. Bijectivity is invariant under swaps.

**WHY_NOVEL:** This is a domain-specific coordinate descent on the initial mapping space, using the actual routing algorithm as the objective function. It avoids proxy cost functions and optimizes directly for routing overhead, which prior placement approaches do not do.

**NOVELTY_SCORE:** 7
**PROBABILITY_SCORE:** 9
**EFFORT_SCORE:** 7
**FEASIBILITY_SCORE:** 10

## Reference: Integration Point in Qlosure

All ideas slot into `init_mapping()` by populating `self.mapping_dict` and `self.reverse_mapping_dict` before `run()` proceeds to DAG construction:

```python
def init_mapping(self):
    # CURRENT (trivial identity mapping):
    self.mapping = list(range(self.num_qubits))
    self.reverse_mapping = list(range(self.num_qubits))

    # REPLACE WITH novel placement algorithm, e.g. Two-Phase Anchor-BFS:
    # Step 1: Build interaction frequency matrix from self.access
    logical_qubits = sorted({q for gate in self.access for q in self.access[gate]})
    n_logical = len(logical_qubits)
    lq_index = {q: i for i, q in enumerate(logical_qubits)}

    F = defaultdict(int)
    for gate, qubits in self.access.items():
        if len(qubits) == 2:
            i, j = lq_index[qubits[0]], lq_index[qubits[1]]
            F[(min(i,j), max(i,j))] += 1

    # Step 2: Rank logical qubits by total interaction weight
    interaction_weight = defaultdict(int)
    for (i, j), w in F.items():
        interaction_weight[i] += w
        interaction_weight[j] += w
    sorted_logical = sorted(logical_qubits, key=lambda q: interaction_weight[lq_index[q]], reverse=True)

    # Step 3: Rank hardware qubits by degree
    hw_degree = {p: len(neighbors) for p, neighbors in self.backend.items()}
    sorted_hw = sorted(hw_degree.keys(), key=hw_degree.get, reverse=True)

    # Step 4: Phase 1 — Anchor placement (top-k to top-k hw qubits, maximally spread)
    k = max(1, int(n_logical ** 0.5))
    anchors = sorted_logical[:k]
    placed = {}           # logical → physical
    placed_inv = {}       # physical → logical
    available_hw = list(sorted_hw)

    placed[anchors[0]] = available_hw[0]
    placed_inv[available_hw[0]] = anchors[0]
    available_hw.remove(available_hw[0])

    for anchor in anchors[1:]:
        # Choose hw qubit maximally far from all already-placed anchors
        best_hw = max(available_hw,
                      key=lambda p: min(self.distance_matrix[p][placed[a]]
                                        for a in placed))
        placed[anchor] = best_hw
        placed_inv[best_hw] = anchor
        available_hw.remove(best_hw)

    # Step 5: Phase 2 — Satellite assignment via BFS from best-interacting placed neighbor
    for lq in sorted_logical[k:]:
        lq_i = lq_index[lq]
        # Find already-placed qubit this lq interacts with most
        best_neighbor = max(
            (q for q in placed),
            key=lambda q: F.get((min(lq_i, lq_index[q]), max(lq_i, lq_index[q])), 0)
        )
        anchor_hw = placed[best_neighbor]
        # BFS from anchor_hw to find nearest free physical qubit
        visited = {anchor_hw}
        queue = [anchor_hw]
        assigned = False
        while queue and not assigned:
            current = queue.pop(0)
            if current not in placed_inv:
                placed[lq] = current
                placed_inv[current] = lq
                assigned = True
                break
            for neighbor in self.backend[current]:
                if neighbor not in visited:
                    visited.add(neighbor)
                    queue.append(neighbor)
        if not assigned:
            # Fallback: first available
            for p in sorted_hw:
                if p not in placed_inv:
                    placed[lq] = p
                    placed_inv[p] = lq
                    break

    # Step 6: Build self.mapping_dict and self.reverse_mapping_dict
    self.mapping_dict = dict(placed)           # logical → physical
    self.reverse_mapping_dict = dict(placed_inv)  # physical → logical

    # Assign any unmapped logical qubits (single-qubit only) to remaining hw qubits
    unmapped_hw = [p for p in sorted_hw if p not in placed_inv]
    unmapped_lq = [q for q in self.access
                   if q not in self.mapping_dict and len(self.access.get(q, [])) == 1]
    for lq, hw in zip(unmapped_lq, unmapped_hw):
        self.mapping_dict[lq] = hw
        self.reverse_mapping_dict[hw] = lq

    if self.use_isl:
        self.isl_mapping = dict_to_isl_map(self.mapping_dict)
```

**Key variables available to all placement algorithms at `init_mapping()` time:**
- `self.access` — gate→qubits (logical), available immediately
- `self.backend` — hardware adjacency list
- `self.distance_matrix` — precomputed all-pairs hardware distances
- `self.num_qubits` — physical qubit count
- `self.data` — raw circuit metadata including `qasm_code`

**Variables NOT yet available at `init_mapping()` time** (computed later in `run()`):
- `self.access2q`, `self.dag_dependencies_count`, `successors2q` — must be precomputed inline if needed by the placement algorithm
